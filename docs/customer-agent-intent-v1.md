# 操作意愿与原话依据

2026-10-24，用户授权先修操作意愿，再做代表性多轮验收。原六条真实验收B02把“还能在原单补充吗”理解为MERCHANT_REVIEW，程序按该目标生成多余摘要。根因是理解合同把业务话题和当前言语目的混在一起；没有证据表明需更换SDK或增加Agent。

本批保留goal，由模型区分信息咨询与明确准备请求。非EXPLAIN焦点新增operation_request，摘取当前用户原话；EXPLAIN省略/null。程序在任何事项/记忆更新接受前核对原话确实属于current_request，禁止从旧轮意愿、助手文字或改写中取依据。该字段只在理解阶段内部使用，转Understanding时移除，原Java/OpenAPI/领域权限不变。

成对提示区分：“还能补充吗”是能力咨询；“能帮我整理摘要吗”是礼貌请求，不能按问号或关键词路由。程序只能保证出处与合同一致，不能单靠原文包含关系证明语义是操作请求。格式错误仍仅一次反馈修正，不改写模型目标兜底；同run冻结manifest，旧已完成结果保持。

先测试原真实坏目标拒绝、礼貌请求/信息问句/撤回、伪造历史出处，以及拒绝目标未污染事项状态；再回归SDK/PG恢复。随后新冻结三组十轮真实流式对话，覆盖插问/恢复/纠正/结束、能力咨询→礼貌准备→撤回，以及政策前提/假设。只执行一次，评测结果决定可否冻结，失败不追加付费追题。单轮上限仍12模型/120秒，整批最多40实际请求；不建Case/核查单/退款，旧44轮和六条结果保持。
