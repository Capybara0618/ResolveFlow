# 建议、补证责任与停止来源改进

2026-10-06，依据[来源审查](../reports/agent-rag-source-review/README.md)接续。仅改现有单Agent的输入提示、结构反馈和运行记录；不改政策排名、Gold、Java审批、金额或客户回调协议。进度只维护tasks/todo.md。

1. 在既有P1解释提示中指明已读的当前退款占用和业务读取失败，保留Observation短编号。按来源取最后一次读取，旧成功不遮蔽新失败，失败不生成可引用事实。提示不替模型选择最终动作；P2原字段、来源、版本、冲突仍保留。无阻碍不增加阻碍段，不能因为没有阻碍段就证明具备退款资格。
2. ASK_CUSTOMER只问客户能提供的内容；已知系统字段（付款、履约、退款槽、承运结论、人工核验）须工具/商家核查，不向客户索要权威字段。只拦截明确的结构字段，不做自然语言关键词分类器。REQUEST_INFO建议必须明确missing_evidence且不得为空白；它仍是给商家的建议，不自动变成QUESTION。系统缺口用只读调查或转人工，沿用已有一次修正。
3. finding的引用结构错误给具体路径、未在evidence_refs中的来源或CONFLICT来源数；归类SOURCE而非笼统FORMAT。模型自行改正或删除不支持的finding，不自动补来源、伪造冲突或增加纠错轮次。严格模型/核心契约原检查继续执行。
4. SDK结束循环使用的占位回复标为HARNESS；有效模型终局标为MODEL。停止轨迹为STOP/REFUSED并带真实reason，不作为ESCALATE/DECIDED或有效decision。占位协议不开放给模型，已持久原响应和真实用量不改。有效ESCALATE仍是模型动作，给简短阻碍及商家下一步的提示；不由脚本编造模型摘要。FAILED回调沿用现有协议：有效模型转交保留其reason_codes或人工核验默认码，不能发COMPLETED当转交原因；Harness失败仍保留真实终止码。该协议不携带summary，模型完整转交摘要尚不在商家失败时间线展示，不扩展Java/UI接口来假称已实现。
5. prompt/context/verifier/code变化进入新manifest；旧run/回放不得静默换版本。另建独立mock回放包，默认入口同步，历史包和来源报告保持。源码改变后旧21输入来源审查需在原版本复算，不能改旧hash让它通过新源码。

先失败注入及不同来源/字段/占用状态变体验证，再集中SDK、上下文、引用、回调、真实隔离PG恢复与strict回放。无新增收费模型或生产队列消费；工程通过不等于真实模型建议准确率提升。记录失败、未运行和适用边界。
