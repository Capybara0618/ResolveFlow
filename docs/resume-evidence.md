## 每条证据卡的格式

从对应C任务开始累积，C13复核后在本文件追加实际卡片或链接到已有报告，不另建进度账本：

- **候选主张 / K编号 / 对应任务**：一句描述做了什么、解决什么问题；标记计划、局部验证或完整验收及证据日期，进度仍以todo为准。
- **个人设计与取舍**：为什么选此方案、替代方案是什么、范围限制；只归属实际完成并能解释的工作，不把AI生成内容自动当作个人熟练掌握。
- **代码与测试**：相对仓库路径+关键类/函数、源码hash；至少一个关键失败场景及实际测试命令/结果，含跳过与未运行。
- **报告与演示**：已有报告链接、原始数据/计算入口、复现命令、预期可见行为；只引用已存在产物，目标路径标“待产出”。
- **指标与条件**：有价值才填写，注明样本/分母、资源、对照、mock/live/合成、冷/热；同一实验的数字不反复包装成多个独立成果。
- **面试追问与限制**：准备“为什么这样做、失败如何处理、验证哪里不足”；保留负面结果和无法保证的窗口。

已有正确性证据但尚无效果对照，可以写“实现了某能力”，不能写“提升了某效果”。C13先核对证据再选5–7条，指标嵌入相关贡献，不强制每条量化，不用代码行数、组件数或测试数替代成果。无法解释的实现应先补理解与复现实验，再作为面试主张。
