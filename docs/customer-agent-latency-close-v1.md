## 服务端改动

上批两个复杂请求各4模型调用：理解→选择订单物流→生成政策Query→回答；有效首正文5.28/4.53秒。模型已知道需要政策条件，且一般条件Query不必等待订单事实时，可以在READ_FACTS附可选policy_query，一次声明独立的订单、物流及条件检索。程序仍逐项经原execute执行和记journal，政策另计local_read，只在POLICY也是当前缺口时接受。

policy_query是模型选择的非空1–1000字符问题，不接受主体/版本等额外参数；不替客户陈述作事实认定。两类事实若需要先后依赖、Query必须看事实再生成，可保持原逐步读取；事实与预期不符仍能补查。程序不自动生成Query、不强制全工具路径，不删除必要政策或改RAG排名。

目标是把适用场景的同证据模型请求4→3，并在固定小样本观察复杂请求有效首正文能否落到4秒内；该目标仅用于本批工程取舍，不作为生产SLA或简历统计指标。预热另列，不掩盖真实失败或追加追成功。
