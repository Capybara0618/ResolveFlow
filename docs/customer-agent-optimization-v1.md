# 客服Agent运行与回答优化 v1

2026-10-21用户授权开始，依据真实模型v2的来源选择、格式纠错、故障交接与条件遗漏问题。进度仅tasks/todo.md顶部；保留旧输入/评分/原始结果，不更换AgentScope/模型/检索算法/依赖锁。

1. 工具目录同时用于实际模型上下文与SDK：独立用途、准确参数和合法动作示例，区分实时事实、商家资格政策、平台操作指南。继续模型选择行动，不按问题关键词强制工具顺序，不预置某题答案。
2. 格式错误一次纠正要指出字段和正确动作形状；未知引用列出本run合法编号。仍校验闭合协议，不静默改模型输出，不增加循环或未记账调用。
3. 工具不可用时记录连续结果和可重试性。允许有界重试，重复不可用后停止该查询的外部调用，给模型明确反馈说明缺失与可用替代来源。模型仍决定说明故障、读指南或整理核查摘要；不伪造商家已经接管。最终预算/无进展停止保留，恢复从持久工具结果重建故障状态。
4. Java冻结可信会话状态（当前消息接收方、是否有核查单及其状态、界面初始接收方），Python实际请求展示；客户陈述与系统状态分别保留，不能从用户文字推断工单已经创建。可选新context字段兼容旧输入，没有状态时明确未提供。
5. 回答指导要求覆盖当前诉求、引用已读来源、区分流程/资格/实时事实并保留决定性条件和例外。确定性门禁只检查可验证的结构、来源和范围；不以硬编码政策ID/关键词匹配冒充自然语言完整性证明。

每步先关键失败测试，独立变体覆盖协议错误、恢复、持续失败/稍后成功、物流无需知识检索等路径。3–5核心文件纵向提交并普通push核实。最终在新版本12场景一次真实模型对照中沿用旧业务文本/事实/评分，只换run身份，说明同开发题回归非盲测；新会话状态用工程测试独立验收，不伪造到旧事实快照。沿用用量账本和生产预算，失败保留、不自动刷分。报告区分运行成功、业务语义、效率和未验证项。

真实回归冻结在evals/customer-agent-live-v3/cases.json，使用scripts/customer_agent_live_v3.py委托已有实际ASGI/记录驱动；逐字段核对业务输入/事实/预期与原v2一致、仅新运行身份，绑定旧两份原始结果和语义报告hash。实际生产guidance/recovery模块单列源码hash。当前Java会话状态接线通过隔离MySQL/HTTP与Python请求测试，真实回归沿用原没有该字段的快照，不能把本轮收益归因为新增系统状态。12题均已用于开发，结果只作同输入版本回归。
