# 模型选择的独立事实合并读取

2026-10-24，接续政策依据修复后分析首正文等待。范围仅客服orchestrated-v1协议、原SDK执行与恢复；不并行改数据库/Java，不减少必要依据。

## 关键路径与设计

上批网页单例首正文6.49秒，GUIDE/ORDER/SHIPMENT/POLICY的activity时间合计约0.323秒，其余约6.166秒包含模型决策、SDK/网络/上下文/持久化和调度，不能当纯模型耗时。原路径5个模型请求：理解→选订单→选物流→选政策→回答。订单与物流接口都绑定同一订单行，入参为空，读取独立时可由模型一次选择。

新增`READ_FACTS`，形如`{"kind":"READ_FACTS","tools":["get_order_context","get_shipment_trace"]}`，两工具可反序；只有当前必要依据同时缺ORDER与SHIPMENT才接受。模型自主选择是否合并；只需一项、需看前项结果再决策时继续READ_TOOL。不能携带主体、参数、政策Query或写工具，两项各一次。

协议经原SDK映射为内部只读组执行，子项按声明顺序调用原execute路径，每项独立预算、fence、journal、来源/失败、activity；不做并发读取。程序没有按意图直接预取整条工具链，也不代替模型生成政策Query。减少的是两独立读取之间的一次模型决策，不减少两次业务读取。

## 恢复与验收

子项保留原工具位置，已完成项恢复复用；第一项完成、第二项未开始时可接续第二项；已STARTED但没有结果仍明确INTERRUPTED_TOOL_RESULT，沿用原边界，不静默重新发送。第一项后fence变化必须阻断第二项。原manifest代码hash覆盖engine/orchestration/prompts，旧run不升级。

先失败测试，再比较同证据脚本：单读5请求、合并4请求；两种顺序、非法工具/主体/重复、单需求、预算耗尽、源失败、流式及PG完整/部分恢复和fence均验证。脚本调用减少不等于真实延迟改善；需要有限真实生成确认模型采用率、解释完整性与实际首正文时间。不能为了快删除政策核验步骤。报告见[工程证据](../reports/customer-agent-fact-batch-v1/README.md)。
