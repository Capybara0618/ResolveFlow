# 客服对话变化与来源化陈述实施

2026-10-21。用户批准先修改意图理解和上下文闭环。依据[企业工程调研](customer-context-engineering-review-v1.md)，保留AgentScope唯一循环、原模型/预算/工具/RAG，暂不运行正式效果评测或修改简历。进度只在tasks/todo.md顶部。

## 本批设计

- 同次动作附`memory_updates`：只记录客户原话中的收货陈述、排查、诉求/偏好、材料与其他事项。每条有稳定id、受控主题、原文引用/字符offset/quote；程序核验当前输入或已读客户原文。条目是CUSTOMER_CLAIM，不是工具事实；不提供可由模型写入的付款/物流/退款系统字段。
- 修正用显式supersedes链接同主题旧条目，旧原话不覆盖。不同信息可并列，不能自动按最后一句抹去冲突；是否属于纠正由模型提出，原文定位与结构约束由程序验证，语义正确另评测。明确撤回可标记RETRACTED，不能伪造客户否定。
- 当前有效条目独立注入请求，不跟随历史窗口一起裁掉。保留原文读回、完整工具/政策及失败状态；数量/窗口不足时明确失败，不静默删掉陈述。跨轮使用同会话最新成功run的受作用域绑定状态，不把旧工具事实或旧O/P编号带入。
- 同次模型动作附`dialogue_events`，表示ADD、CONTINUE、CORRECT、CANCEL、PAUSE、RESUME、CLARIFY；每项关联任务及本轮客户原句。临时插问表示暂停旧任务+新增子任务，永久切换表示撤回旧任务+新增任务；不是新增固定流程或文本关键词路由。
- 任务增加SUSPENDED，跨轮仍可见并支持恢复。前轮未完成任务不能静默消失；旧引用和回答片段清除。每次状态更新先完整校验，失败不污染此前有效状态；继续沿用一次精准纠错机会。
- 公共客户消息/商家报告保持原协议；内部状态存在既有answer开放对象/run结果，Java冻结给下轮。共享仍需客户确认，内部记忆不直接公开给商家。无新表/依赖/后台循环，无跨商品长期画像。

## 纵向小步与验证

1. 来源化陈述与同次动作接线：先红测原文伪造、纠正、并列冲突、错误动作回滚、预算保留，再实现/验证/提交。
2. 对话事件与暂停恢复：先验证插问/恢复/撤回、漏旧任务、未来/助手原文不能授权客户变化、一次纠错与相同run恢复，再实现/验证/提交。
3. Java跨轮冻结及Python加载：同商品恢复陈述、最新纠正、不同商品隔离、旧版本拒绝、内部字段不进客户/商家投影。真实隔离PG与MySQL/HTTP验证，最终记录工程结果和剩余质量问题。
