# 验证与面试证据 · v1.2核心

减少实验组合，不减少保留路径的正确性。这里的数量是核心实验设计，不是已有结果；历史T00–T02测试数量不代表业务已完成。

## 1. 记录

每份报告保存源码commit/hash、依赖/模型/Prompt/manifest、硬件/容器限制、seed、样本版本、原始输出、失败/超时/跳过、统计脚本和实际命令。mock/live、合成/真实来源明确标记。没有Git或外部模型版本不可固定需注明限制。

金额/权限/状态测试在真实MySQL/PG/MQ上集成验证，不能用内存mock代替事务语义。核心CI包含格式、单元、旧兼容+核心契约、mock闭环与strict小型回归；收费live不默认进入CI。

## 2. 最小案例集

- 80个合成业务案例：40dev、40冻结test。物流异常、损坏、缺证、冲突、范围外、工具故障覆盖；至少6组同诉求不同证据的配对案例包含其中，家族整组分到dev或test。
- 20个独立安全样例：跨用户/商家、伪造引用/身份、恶意材料、旧revision、授权重放、错误金额。全部做确定性测试；至少10例另做live诱导观察。
- 40条RAG查询，20dev/20test，见policy-rag。
- 至少10个长上下文/冲突/溢出fixture，只验证结构保真，不混进主要模型准确率。

Gold包含允许动作集合、必须证据、禁止动作、政策版本、是否需追问/人工；不规定唯一工具路径。金额/规则由确定性fixture生成；至少人工审查20个分层样例，记录真实检查数。test不得用于调Prompt，改后需新保留集或明确披露。

## 3. 模型比较

只要求B1固定调查workflow与A动态Agent。两组同模型版本、政策、权限、案例、相同调用/Token上限；B1实际走固定证据工具链，不给Gold或额外权威资料。工具和模型真实成本全部计入，失败/超时不可删除。

冻结test每组完整跑1次；再对预先选定的12个代表性test案例各额外跑2次，两组都跑，单独报告波动，不把重复案例当新的独立样本。没有足够API预算时先报告阻塞，不将mock效果充当live。

报告：动作正确数/全部case、必要证据覆盖、支持结论的引用精度、应人工样例召回、违规建议/实际违规执行分别计数、每case累计输入/输出与成本、p50/p95时延。UNKNOWN费用单列已知值与估计上界。

小样本比例给分母和Wilson区间，重复分层单列；不预设85%准确率为“成功事实”，不要求动态Agent必然赢。核心完成要求实验真实且分析失败，实际违规执行必须0；出现问题要修复后重测且保留旧报告。

## 4. 核心故障矩阵

| ID | 注入 | 关键结果 |
| --- | --- | --- |
| CF1 | Outbox提交后发送前崩溃；发送成功但SENT未保存 | 可重投、不丢工单/命令 |
| CF2 | 消费事务提交后ACK丢失、重复/乱序结果 | inbox防重复，权威终态不被旧消息覆盖 |
| CF3 | provider退款成功后丢响应/延迟可见 | UNKNOWN保持预留，查询收敛，一次资金效果 |
| CF4 | 同line及同订单余额并发退款 | 金额不超额、单行最多一次成功 |
| CF5 | 旧revision回调、审批与撤销/消费竞争 | 旧方案不执行，消费后禁止修改，线性化明确 |
| CF6 | 模型响应落库前/后崩溃、旧worker返回 | 已落库复用，未知可重复计费，fence保护checkpoint/回调 |

每类至少5次可复现运行，CF4用100个并发请求覆盖同line以及不同line争余额；固定注入点/seed。单元测试另外覆盖所有合法/非法状态迁移，不因矩阵只有6类而省略其他安全约束。

依赖恢复后报告恢复/未决数和耗时，保留UNKNOWN占用优先于强行成功。不把“5次没错”写成生产可靠性保证。Redis故障、工具timeout和模型限额在相应模块测试，不再强制独立大型故障平台。

## 5. Harness与回放

H1–H5按agent-harness要求验收。strict最少5个完整golden packs；损坏/缺记录/不支持轨迹分别拒绝，禁止任何业务写和网络回源。回放覆盖范围只写实际支持类型。

上下文必保留字段/hash与原文scope测试必须通过；不要求三组live上下文消融。若宣称成本优化，需要另做同模型/样本质量+累计成本对照，不用单步长度替代总成本。

## 6. 后端性能与演示

只选一个实际高频读路径（订单摘要或工单列表），固定至少10000订单行/1000工单，10和30并发，每档预热30秒、稳态60秒，优化前后各重复2次。记录索引/缓存条件、冷/热、资源、成功RPS、错误率与p50/p95。内存不足可调规模但如实注明，不比较不同负载并宣传同条件提升。

五个演示：物流自动退款；损坏补证人工审批；UNKNOWN查询收敛；不同证据驱动Agent路径变化并拒绝恶意材料；worker恢复及选定轨迹strict回放。允许一个演示串联多个行为，不另造复杂UI。

## 7. 完成判定

C00–C13核心任务通过，CI-01–10有测试，6类故障、B1/A live对照、人审抽查、RAG基线、一个性能对照、5个演示有真实报告，即核心版完成。原18类故障、240案例、9演示、反事实及T39全量消融均不阻塞。

费用需用户确认额度，不启动无限API调用；安全性不能用平均准确率抵消。没有实测收益仍可展示正确实现和分析，不填虚构百分比。
