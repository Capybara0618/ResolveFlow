# 购物体验三批实施方案

2026-10-29，按作者已认可的产品设计分三批推进。各批先完成代码、数据库迁移、协议与自动化检查；三批完成后统一启动服务进行真实场景验收。拍摄继续暂停，当前进度只维护tasks/todo.md顶部。

## 第一批：身份、收货与下单

本人昵称和图片头像、聊天三方身份、地址簿、两个结算入口、订单固定收货快照。详细规格见[购物基础功能](shopping-basics.md)。公开评价保留匿名，使用统一默认头像；本人评价编辑器使用本人头像。

## 第二批：消息与下一步

站内消息以现有消息、核查与工单事实为来源。买家收到商家回复、待补材料、退款结果提醒，商家收到咨询新消息及待处理事项；点击回到相应会话或申请。已读状态按本人持久化，重复读取不重复产生通知，不能读到其他买家或商家的消息。

订单列表按购物阶段组织：待付款、待发货、待收货、已完成和售后。阶段由已有付款、退款及可信履约事实推导；物流未知保留明确状态。签收可展示已完成，本批不新增改变评价或售后资格的人工确认收货动作。个人中心“售后”进入完整申请列表，订单中的“退款”按账本退款及预留事实筛选，避免漏看尚在调查的申请。

个人中心统一订单、售后、资料、地址与消息入口。登录后回到原商品；添加地址回到原结算；物流与消息保留返回原订单或列表的路径。异步写入和结果待确认期间保持原请求，错误保留已填内容。

## 第三批：商品、店铺与账号入口

商品支持多图展示、规格参数及配送和售后说明。商家可以上传商品图片、调整顺序、预览；图片服务复用经过校验与重新编码的媒体能力，商品公开媒体与账号私有头像采用不同读取权限。

店铺具备头像、简介和联系入口，商品、订单及客服展示统一店铺身份。商家只能维护本店资料和商品，更新保留版本控制，不改动已付款订单商品快照。

增加访客注册入口及账号找回路径。账号凭据沿用现有密码哈希和会话失效机制；注册不授予商家或平台权限，找回不能仅凭可公开获知的账号名重置密码。具体找回证明方式按已有能力实现，不伪造邮件或短信发送。

## 统一验证

三批检查按功能集中进行，使用独立测试容器与合成资料，不清理现有订单、不污染专用演示账号。代码通过后再统一验证注册/登录、资料和地址、选购下单、商家处理、客服与退款提醒以及返回路径，并区分自动化检查与真实场景证据。

注册及找回具体采用用户保存的恢复密钥，已有账号可验证当前密码生成；无恢复密钥时由既有平台管理重置。商品上传素材与账号头像分开鉴权，媒体目录与数据库共同备份；商品多图保存不追改订单快照或已发布政策。


## 统一场景验收清单

1. 新买家注册，保存恢复密钥，登录；既有买家从账号安全生成密钥；找回后旧登录失效。
2. 修改昵称、上传头像、保存两个地址、切换默认地址，刷新与重新登录后仍一致。
3. 立即购买与购物车结算均选择地址，无地址时不能提交；付款后修改或删除地址簿，订单收货快照保持原内容；对应商家可看，其他商家不可看。
4. 商家上传商品多图、调整主图顺序、编辑参数及配送/售后说明；商城主图和详情一致；未发布图片及私有头像不能从公开商品图片入口读取。
5. 更新店铺头像、简介、联系信息；商品、订单、咨询的店铺身份一致，旧订单商品快照保持原信息。
6. 用新验证账号走客服与商家核查：消息双方头像正确，私聊不能被商家读取；回复、待补材料、退款结果提醒直接进入对应会话/申请，已读刷新保留。
7. 购物阶段与付款/物流/退款事实一致；物流未知有明确提示，返回保留原订单筛选。新注册、登录及资料管理不丢失原商品返回路径。
8. 最后检查窄屏/桌面布局、网关上传和服务重启持久化。新验证数据独立于卡皮巴拉拍摄账号，历史交易不清理。

这些是代码完成后的真实验证清单，不能从自动化检查结果直接勾选通过。
