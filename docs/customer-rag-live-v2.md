# 客服RAG真实模型验收 v2

2026-10-21用户授权接续。目标是验证当前Agent能否按问题选择知识来源、生成聚焦Query、使用适用依据回答，并记录完整Python接口答复耗时。当前进度只记tasks/todo.md顶部。

## 固定范围

12个合成诊断场景，5个流程指南、4个政策、2个事实/故障、1个事实+政策+入口混合。输入和逐项语义标准在evals/customer-rag-live-v2/cases.json中冻结，运行前记录源码/资产/依赖锁hash。部分业务主题与旧开发题重叠，明确非盲测/真实用户集，不声称泛化准确率或三路相对旧dense的因果收益。

使用当前SupportRuntime/AgentScope/BoundSources/ASGI接口，真实DeepSeek Flash现有配置、真实BGE与保留PG固定商家政策generation。订单/物流HTTP由冻结合成快照提供，失败场景明确返回503；这只验证Agent如何消费工具结果，不验证Java故障接线或实时业务数据。当前业务服务继续停止，不消费历史队列，不创建交易/退款/核查单。

流程问题按需完整读取指南，政策问题搜索本店版本，实时事实由工具读取。评分接受合理工具顺序和必要补查；不把单次调用顺序当固定工作流。最终答案要覆盖冻结业务条件、引用真实已读来源、区分已知/未知和申请/批准/到账。工具选择、Query保真、必要条款覆盖、答案语义分别判定；来源覆盖不等于答案正确。

每场景只跑一次新run，沿用生产12次模型/16次外部读/8次本地读、120秒deadline和每步窗口限制；不新增累计消费上限。沿用tmp/evaluation-live-budget.json计数并加进程锁，每次模型调用前持久记录，超时/失败不免费重跑。正式结果文件独占创建，已开始的场景不作为新请求重试；未落库响应不宣称零重复计费。

只向本批唯一隔离PG schema写咨询run/call，政策库连接强制只读；运行前后public全表hash见证一致。导出实际输入/动作/原始工具结果/模型usage与旁路耗时后清理本批schema，保留原数据卷。API key仅环境读取，不进入输入/日志/报告。日志与报告不得包含响应原始敏感头或密钥。

## 验收与报告

生成模型前先验证驱动的调用记录、失败保留、作用域绑定和已存在结果拒绝；随后提交冻结输入/驱动。模型运行不调生产提示词/检索参数，不按答案修Gold，不自动补跑失败。Codex依据完整实际请求、工具原文和冻结标准逐项语义复核，不调用模型自评，不要求用户另行标注。

报告保留12个分母、失败、未覆盖、实际usage、接口完整耗时/模型耗时/检索耗时。预热在业务计时前单独记，P95注明小样本描述值；不包含Java/浏览器时延。旧P02口语漏召回与当前模型实际Query的结果分开记录；若有缺陷，先完成本批原始报告，再提出通用修正，不能覆写本轮。
