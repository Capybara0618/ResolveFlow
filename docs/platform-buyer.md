# 平台买家身份与跨店售后

2026-10-03，用户批准[多商家设计](marketplace-design-review.md)及[目标图文合同](ui-marketplace-v1/README.md)后实施。本文是第一批的身份/读取/售后协议，不把图片当授权依据；实际完成状态只看[todo顶部](../tasks/todo.md)。

## 身份及迁移

沿用唯一登录入口`POST /api/v1/auth/login`及CUSTOMER角色，区分两种互斥身份：旧客户携带merchant_id/customer_id；平台买家只携带buyer_id，不能混入merchant/customer或通配商家。工作人员仍固定商家，不能携带buyer_id。JWT、数据库和公开登录/profile合同一起约束，空值、伪造混合声明或错误buyer都拒绝。身份版本与启停仍逐请求读取数据库；不承诺撤回已开始请求或已建立SSE。

Case V24追加platform_buyer与buyer_customer_binding，放宽账号表只为合法平台买家允许merchant_id为空，其他身份保留必需商家约束。buyer_id唯一绑定一个登录账号，(buyer_id,merchant_id)唯一，对(merchant_id,customer_id)同时唯一；customer_id不假定全局唯一。旧账号、hash、身份版本、订单/工单归属、actor及政策manifest不改、不合并。绑定只由受控迁移建立，无公开认领、解绑、注册、全平台密码管理接口；演示新增两店关系，不等于自动完成所有历史客户迁移。

新增合成账号`demo-buyer / demo-pass-4001`，buyer_id=B-3001，对应M-1001/C-B3001-M1001、M-1002/C-B3001-M1002。它没有旧客户的订单。商家管理员的人员列表/详情/更新/密码重置仍按自身merchant_id筛选，平台买家不在其管理范围。禁用一个商家只移除该商家的买家可用归属，不停用整个平台买家账号；账号自身禁用/身份版本变更拒绝旧会话。

## 读取与原有售后操作

复用`GET /api/v1/orders`与`/{order_id}`。买家列表对可信归属逐店发送CUSTOMER作用域的内部SERVICE调用，按paid_at DESC汇总，同时间跨店按merchant_id升序，各店内保留Commerce的line_id降序；不向Commerce转发用户JWT或从查询参数取得商家/客户。订单行ID在同一个Commerce库全局唯一，每店至多取limit行；支持limit=1–100，最多20条店铺归属，超出明确失败而非静默截断。任一店下游失败时整页返回503，不把缺店的部分结果当成功。

平台订单游标绑定buyer_id与当前启用的完整归属集合，保存每店已消费的最后一行精确时间/ID；未消费店保留原锚点，每店分别续读（避免Java字符串排序与MySQL字符排序不同导致漏行），不使用offset。内部共享OrderReadCursor的v2编码保留微秒，Commerce继续接受旧毫秒编码。锚点不赋予权限，即使构造游标，资源范围仍取当前可信关系。查询不提供全程数据库快照，订单更新/退款状态可在页面间变化；新插入的较新订单通过刷新首屏发现。

平台订单行增加merchant_id/merchant_name；旧用户响应保持原字段。`GET /api/v1/customer/cases`以可信映射EXISTS查询本人全部申请，保持原阶段筛选和微秒keyset；买家游标额外绑定buyer_id，平台列表增加merchant_id，旧客户投影不变。详情、补证回答、追加、撤销、事件订阅按实际工单的(merchant,customer)匹配后进入原领域服务；创建/资格按各可信归属查询实际订单行，其他客户或商家的资源均404。内部适配身份保留原平台账号subject，仅限已验证资源的调用，不签发第二枚用户JWT，也不能通过登录会话校验。

创建仍由订单行实付/支付时间选本商家政策，幂等键继续按商家隔离，同一买家可在两店使用相同key。授权消费冻结、单行全量退款、UNKNOWN保留同operation、专员负责人/协作版本规则及Agent精确凭证均沿用；平台买家没有审核、退款执行或人员管理权限。

## 合成样本与验收

Commerce V9只追加两条**已支付合成样本**：BUYER-3001-A耳机32900分、BUYER-3001-B台灯12900分，各一订单/账本/初始FREE槽及标识合成的LOST物流。支付时间在现有政策有效期内，便于验证身份与售后接通，不是已实现商城购买/支付的证据。原订单、已退/预留、工单及政策版本保持。

集中验证：平台与旧会话兼容、混合声明拒绝、两店本人列表/精确分页、他人和同customer_id跨店碰撞404、各店申请与政策、本人补证/撤销、买家审核403、管理员无法重置/停用买家、店铺停用与买家身份版本/账号启停、SQL互斥约束。Java用隔离Testcontainers数据库；网页沿用客户工作台先提供跨店订单/申请，M01–M11商城新页面按后续批次构建，不宣称本批已完成商城。具体命令/失败/未运行项见[第一批报告](../reports/platform-buyer.md)。
