# RAG 第四批：可解释检索与可信评测

2026-10-05，用户要求先做好RAG，并指出合成政策/问题/答案同源的评测偏差。本批接续现有Harness，不重建业务数据或重做前批。

## 查询来源

生产：模型读取工单上下文/工具Observation，自主输出`SEARCH_POLICY.query`与top_k；`sdk_runner.py`动作门禁后交`local_reads.py`的政策读取桥，主体/政策版本由可信run绑定，模型无权选商家/URL/版本。没有自动把买家原话转换成query的第二模型或固定规则路径。实际请求/决策/查询/结果记录在原模型和工具日志。

固定RAG评测：`evals/aligned-v2/rag/queries.json`的60条预写问题，Gold另存，但最初由同一`build_assets.py`同时编写政策、问法与规则标签；因此分文件不能证明独立标注或真实分布。mock Agent：`scripts/evaluation/models.py`按观察结果选择几个固定查询，只证明接线。真实DeepSeek轨迹中的query仍来自模型，但其业务事实和政策也是合成的，不是商用用户数据。

## 实施顺序与范围

1. 保留BM25离线对照，冻结旧v1/v2政策/Gold。新增一份预先固定、口语/否定/多依据的诊断查询与独立Gold文件，记录同作者合成、非盲测、待独立复核，不伪称消除偏差。提取已保存真实模型查询作未标注探针，不给所有查询套上终局Gold。
2. 同一固定本地embedding比较当前正文检索与“标题＋完整正文”表示，不增加LLM改写，不修改引用原文/hash。记录top1/2/5覆盖、全部依据覆盖、MRR、候选条款/分数/字数、错误主体/版本、耗时，以及BM25对照。开发集选择方案；已看过的test和新诊断集仅作回归/诊断，不能称盲测。若无明确收益不强上方案。
3. 修正检索可靠性：READY必须对应单一选中generation，不把同manifest多个generation的块混到一起；查询embedding的model/revision/dimension必须匹配索引，异常向量明确拒绝。保留完整条件/例外、权限与引用校验。
4. 按证据决定最小生产修改，先失败测试再实现，集中验证索引/政策读取/SDK/恢复及新版本回放。生产索引不静默重写；如果表示改变，必须说明旧索引和同run恢复边界。

本批不默认加hybrid/RRF/reranker、向量数据库、额外模型或多Agent，不改退款资格或政策内容。相似度用于找候选，不代表适用/授权；无适用条款时返回候选不能单凭检索判错。新增真实付费对照不作为本批完成前提，已有真实query可以离线复测。

## 证明边界

小语料每版本只有9条，top5覆盖大半候选，必须同时看top1/top2和上下文占用。对合成诊断集的改善不能宣传真实客户效果；独立用户问法、独立专家Gold、新冻结盲测仍需后续补充。BM25对精确术语可能有效，dense也可能被相似措辞诱导，采用哪条路径只能据同条件证据判断。保存候选失败、退化和未运行项，不根据排名修改Gold。
