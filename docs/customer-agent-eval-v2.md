# 客服 Agent 多轮真实评测 v2

2026-10-21，用户批准开始新版本准备及评测。范围是现有客服 Agent 的多轮效果、政策依据和效率；不改生产实现或简历，不启动普通业务队列。进度只维护 tasks/todo.md 顶部。

## 数据和主对照

保留 readiness-v1 的 12 类/36 轮输入及评分原文，新增 D13/D14 各 4 轮，合计 14 类/44 轮。两组执行相同 44 轮：自主 Agent 与固定调查流程，各自使用真实前轮回答、任务与客户陈述；失败保留在会话和轮次分母。不混入标准答案，也不从另一组借用回答。数据均为开发者可见的合成资料，不称独立盲测或真实客户数据。

固定组在同一 SupportAgent 上下文、协议、来源、预算、一次字段纠错和持久调用账之上运行评测专用固定调度：先让同模型生成 SEARCH_POLICY Query，再固定读取订单→物流→指南→搜索政策(top_k=3)，最后让同模型 ANSWER。可重试读取最多两次；不能追加自选读取或改写查询。非法阶段动作记失败，字段非法沿用一次纠错。它是明确的固定流程基线，不伪称最优工作流。生产自主组仍由唯一 AgentScope 循环调度，可按观察选择工具、原文读回和查询次数。固定组不加载另一套生产循环。

模型统一使用现有 DeepSeek Flash、temperature=0、thinking disabled、JSON、原 1024 输出上限、12 模型/16 外部/8 本地读取预算、120 秒轮次 deadline；每轮工具/政策权限和检索实现相同。固定组与自主组按会话交替先后，避免一组全部在前；单次执行，不按分数重复付费运行。失败/未知尝试也记录用量。工具读取的固定 HTTP 事实及会话状态明确是合成快照，政策使用保留 PG 的实际不可变 generation，生成模型/ASGI/AgentScope/调用账为真实执行；不冒称 Java/浏览器全栈效果。

## 事先确定的评分

- 主指标：会话完整完成率，所有轮次及必要子问题都正确、可操作、保留关键条件和纠正，无虚构业务动作才计完整；任何一轮部分/失败则会话不完整。另报告逐轮完整/部分/失败，系统失败也入分母。
- 逐轮按 scenarios.json 的每项条件进行源审：对照真实回答、工具、实际政策和历史；不能用关键词命中替代语义判断。完整=全部条件满足；部分=仍有有效回答但存在条件遗漏/错误；失败=无回答或关键判断不可用。记录每项理由、引用缺失、事实或动作虚构。
- 新增场景另报告：暂停后恢复、采用纠正、撤回后停止、是否重复索要已排查信息。任务/事件/陈述结构是诊断证据，业务回答正确性仍优先，不因标签漂亮计通过。
- RAG：记录每次真实 Query、召回规则、Top-K、耗时；对需要政策的轮次复核必要依据是否被读到及最终是否使用完整。不会调用政策的流程问题不计入政策覆盖分母。保留既有 RAG v5 独立检索比较作为引用证据，本次不将其旧分数说成新实验。
- 效率：实际模型请求、provider 输入/输出 token、热态完整 Python 接口 P50/P95、每次检索耗时、冷启动预热分开。两组配对描述，不预设 Agent 降本或更快；小样本 P95 不作稳定承诺。

事先通过条件：工程执行、轨迹、用量和数据保持均完整；业务目标为至少 12/14 会话完整、40/44 轮完整，新增 2 组暂停/恢复/纠正/撤回全完成，无虚构已转交/退款/跨店泄露。目标不满足如实报告，不改 Gold 或重跑刷分。相对固定组的差值用于判断自主调度价值，不把未胜出改写成提升。这些是项目验收目标，不是承诺结果或简历数字。
