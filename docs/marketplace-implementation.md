# 多商家上游实施对应

2026-10-03用户已审查[目标图文合同](ui-marketplace-v1/README.md)并要求开始实施。本路线承接[参照审查](marketplace-design-review.md)的六批依赖，售后五批不重做；实际进度只记[todo顶部](../tasks/todo.md)，本文不维护第二份完成清单。

| 批次 | 图文对应与实施边界 | 集中验证 |
| --- | --- | --- |
| 1 平台买家 | M08/M09及身份状态板：同一登录买两店；可信归属，跨店本人订单/申请，原售后接通。协议见[平台买家](platform-buyer.md)。先复用客户工作台，商城布局随交易批次落地 | 旧账号兼容、复合归属/横向越权、分页、管理员边界、各店政策与本人写入 |
| 2 商品/直接购买 | M01–M04/M06：跨店上架目录、搜索/分类、店铺、SKU/规格、1–配置上限数量、服务端报价及独立草稿；首先单SKU切片，不将其当最终多行目标 | 下架/价格变化/数量、商家与报价、草稿归属、重复请求；公共目录不可返回私有订单/政策资料 |
| 3 支付/本人订单 | M07–M09：模拟支付成功一次原子发布原已支付订单/行、支付账本、各行FREE槽；待支付只留草稿，paid_at不可伪造 | 重复/支付取消竞争、到期、未知结果回查原尝试、金额与归属、旧资金不变量 |
| 4 购物车/多行 | M05/M06：按店分组，单店多SKU结算，其他店保留；先定义并修正行资格/可退额与整单状态，多行不能沿用旧整单未退假设 | 增删/数量/下架/改价、另一行已退后的资格、并发各行预留、合计不超过实付、同行至多一次成功 |
| 5 模拟履约/售后 | M10/M11及售后状态板：本商家交易列表/详情/首次模拟发货，未发货退款政策及当前支付日期有效期；复用既有专员/管理员流程 | 跨店发货拒绝、已消费不能改输入、合成轨迹、未发货正确政策、已申请/已退/UNKNOWN |
| 6 浏览器收口 | 全13视图与既有售后页面：一个买家购物两店，两店各自处理申请，原有自行启动命令 | 1280/1440/1680、主事实16–18px、空/错/过期/未知状态、全链金额/隔离、历史数据保留、mock/live分开 |

范围新增仅为个人项目可演示的购物上游。沿用三Java进程/Python Agent和依赖锁；不做完整黑马商城、库存锁/超卖、跨店合并支付、真实支付、营销、公开商家入驻、移动端或平台超级管理员。核心仍为Agent/RAG辅助的可靠售后，付款和物流明确模拟。

未来模块开工前把其状态/请求/响应/不变量补进专题规格与核心OpenAPI，再执行失败回归和实现；不一次铺全量占位API。位图中的按钮不能替代后端能力，不新增无作用的小字、营销标签或虚构数据。前端围绕主要商品/卖家/金额/状态与动作；旧兼容协议保持，迁移只追加。
