## 用户体验

商城账户菜单增加“个人资料”和“收货地址”。页面沿用暖白、深绿和现有字体；以表单和布局表达用途，减少辅助说明。

个人资料展示头像、昵称和账号。用户可修改昵称，选择默认头像或上传图片；账号标识保持稳定。演示账号显示名为“卡皮巴拉”，使用独立演示数据。

地址簿包含收货人、联系电话、省市区、详细地址和默认地址，支持新增、修改、删除、设为默认。首个地址自动设为默认；修改地址时不改变已生成订单。

“立即购买”和购物车结算使用同一收货信息区。优先展示默认地址，允许切换及新建；没有地址时展示“添加收货地址”。填写并选择地址后才能提交订单。商品、数量、金额与地址集中核对。

买家订单详情和商家订单详情展示订单保存的收货信息。旧订单显示“该订单未记录收货信息”，不会用当前默认地址补写历史。

## 头像与聊天身份

- 用户头像是账号资料的一部分，页面刷新和重新登录后仍能恢复。
- 顶部账户菜单、个人资料和聊天消息复用同一头像组件，包含加载失败的默认图。
- 买家消息显示买家头像，商家消息显示商家头像，助手使用统一的品牌头像。商家共享原文、历史会话和正在生成的消息也遵循此规则。
- 消息以实际作者身份确定头像和昵称，不能按当前登录者或消息接收方推断。头像只承担身份展示，不改变消息权限。公开商品评价继续匿名为“已购用户”，使用统一默认头像；本人评价编辑器显示自己的头像，不公开真实账号或私有头像。
- 头像在昵称旁保持紧凑尺寸，聊天正文沿用现有字号；用户消息和客服消息都保留清楚的阅读方向。

上传先支持PNG/JPEG，限制文件体积和解码后尺寸，服务端校验实际图片格式、重新编码并移除元数据。媒体存入独立配置目录，不使用客户端文件名作为路径，不写入Git。读取沿用已鉴权的本人/会话参与者范围；前端通过鉴权请求获取图片，不能开放任意账号资料查询来换取头像显示。

## 数据与职责

Case管理账号资料和按buyer_id归属的地址簿，复用现有认证。个人资料接口从当前登录者确定主体，不接受客户端传入另一个用户身份。头像与昵称不进入退款授权计算。

Commerce保存订单收货快照。Case校验地址属于当前买家后，向Commerce发送可信收货数据，不能信任浏览器自行提交的地址归属。结算草稿冻结已选地址版本和内容；用户在提交前切换地址并重新确认，提交后草稿保存固定快照。付款沿用该草稿；需要换地址时取消未付款订单并重新提交。付款创建订单时在同一事务中关联已冻结的收货快照。实际接口字段、类型和fixture随实现同步。

地址编辑和默认切换使用版本校验；默认地址更新串行化到同一买家，避免并发产生多个默认地址。删除地址与下单并发时以提交时的归属、有效性和版本检查决定成功或明确要求刷新。

订单幂等身份同时约束商品与收货快照；同一请求标识换地址不能悄悄生成另一笔订单。地址簿后续变化不覆盖订单快照。原订单及退款事实不迁移、不重算。

地址和电话仅交给本人及对应订单商家。Agent原有订单/物流工具继续返回业务所需字段，不自动附加完整收货地址、电话或头像文件。报告、错误日志和README素材不记录真实个人收货资料。

## 实施顺序与验收

### 已定义的资料与地址接口

接口通过当前登录会话确定账号；响应均使用JSON，头像读取返回PNG。资料`version`、地址`version`与登录身份版本独立。

| 接口 | 请求及响应 |
| --- | --- |
| GET /api/v1/account/profile | 返回username、display_name、avatar_id（可空）、version |
| POST /api/v1/account/profile | display_name、expected_version；返回当前资料 |
| POST /api/v1/account/avatar | multipart file、expected_version；返回当前资料 |
| POST /api/v1/account/avatar/reset | expected_version；恢复默认头像 |
| GET /api/v1/account/avatar | 本人当前PNG头像；未设置时404，前端显示默认头像 |
| GET /api/v1/account/addresses | items地址列表，包含address_id、recipient、phone、province、city、district、detail、is_default、version |
| POST /api/v1/account/addresses | 收货字段与is_default，新增地址 |
| POST /api/v1/account/addresses/{id} | 收货字段、is_default、expected_version，更新本人地址 |
| POST /api/v1/account/addresses/{id}/delete | expected_version；软删除，成功204 |

版本冲突409、未登录401、地址越权404；非买家操作地址403。地址最多20条。默认切换使受影响地址版本递增；删除默认地址后从剩余地址选一条作为默认。头像通过RESOLVEFLOW_USER_MEDIA_DIR配置持久目录，默认tmp/user-media；备份时包含此目录与数据库。

1. 个人资料、图片头像存储与鉴权接口；前端资料编辑及公共头像组件。
2. 买家、商家、助手聊天头像和昵称接线，覆盖历史消息、共享消息、生成中状态及图片加载失败。
3. 地址簿持久化、归属校验、版本控制、默认地址及前端管理。
4. 两个购物入口选择地址、结算确认、订单快照和商家查看；兼容旧订单。
5. 集中验证资料持久化、头像上传/读取、越权隔离、默认地址并发、结算幂等及快照不漂移，再验收一笔新订单的购物与售后。

## 结算及聊天身份协议

`contracts/core/openapi-account.yaml`和`fixtures/account.json`描述本人资料、地址簿、消息作者身份及订单收货信息；结算选择与可信快照同步于Case/Commerce OpenAPI、共享Java Wire及前端类型。公开请求必须选择shipping（address_id、expected_version），浏览器不能提交shipping_snapshot。Case先用原请求确认是否已落库，未创建时读取本人当前地址并传给Commerce；地址已修改或删除后仍可用原请求读取已经创建的草稿，不能用旧请求换地址。

收货快照存于checkout_shipping，以draft_id唯一关联；创建草稿与快照同事务。支付创建订单并关联原草稿，保留原快照；购物车重试也使用原请求版本和地址。旧订单返回shipping=null，页面明确未记录，不推断地址。本人GET /api/v1/shop/purchases/{purchase_id}/shipping、商家GET /api/v1/merchant/orders/{order_id}/shipping；内部读取只授予commerce:checkout，Agent读取凭据不能调用。

消息作者接口按现有会话投影检查可见性：买家私聊不因创建核查单而公开；商家只可读取明确共享原文或双方核查消息的作者身份。助手使用统一品牌头像，无图片文件；未上传/读取失败时使用默认头像。
