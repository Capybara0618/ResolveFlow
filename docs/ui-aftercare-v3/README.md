用户已授权“先预期图，再按图修改”。[五页图册](index.html)覆盖买家列表、申请、详情/补证，商家列表、审核详情。[生成提示词](prompts.md)记录内置image_gen输入，图不是运行截图。原图册/旧实现保留，不重启旧任务路线。

## 图文合同

共同规则：沿用现有ResolveFlow品牌、蓝白配色和商品插画组件，不依图创建新账号/商品/金额。商品在申请、工单列表及详情都显示图片、名称、规格、数量、本行实付；历史无图时明确“图片未提供”，不能按名称猜图，也不能读当前目录替换下单快照。展示与资金读取分开。

| 视图 | 落地结构 |
| --- | --- |
| 买家售后列表 | 复用商城四入口导航，取消重复侧栏；店铺+商品卡片+处理状态+详情/补充材料。筛选紧凑，查询明确只查已加载申请，默认不铺UUID/行号/刷新机制说明。 |
| 买家申请 | 原商品卡片+情况说明+可选文本材料+申请金额和提交；已有请求键/结果待确认冻结原输入不变。图中退款原因归入现有情况说明，不额外造新的业务字段。 |
| 买家详情/补证 | 状态与下一步、商品卡、原申请/文本材料、当前问题和回答；历史问答/技术编号/完整轨迹展开读取，当前问题和过期/UNKNOWN/冻结提示直接可见。 |
| 商家列表 | 单商家五入口沿用；卡片显示商品/实付/诉求/状态；列表与详情分开，不再三列挤压。保留分页、服务端筛选、更新提示和原负责人权限。 |
| 商家审核详情 | 商品摘要→原申请/可核验材料→Agent建议与关键引用→人工审批；订单/执行、完整轨迹、原始工具记录、绑定政策全文可展开。核验入口和决定理由仍可操作，旧建议失效、服务端拒绝、UNKNOWN直接显示。 |

正文、必要说明、按钮、状态和表单≥16px，标题22–30px，金额20–26px；使用宽度/留白/字重区分层次。桌面1280/1440/1680检查，无移动端新增要求。长编号/JSON允许换行或区域内滚动，不挤压主信息。

生成图存在样例偏差，实施以此合同和真实协议为准：个别图画了“个人中心”、深色侧栏、换货文案、买家显示名及未核验的“人工核验记录”；正式页使用现有四入口和浅色商家五入口，只支持单行全量模拟退款，只显示实际存在的材料/姓名。图片为商品插画，无上传照片/视频功能。图上的时间、履约、政策、金额和后续进度不是事实模板，须由服务端返回；不能自行补出已发货/批准/到账或未发生的时间线。批准授权与执行完成分开，模型建议不等于权限。

## 实施顺序与验证

1. 先补展示数据：受现有身份/租户范围保护的商品行读，图片取已付款SINGLE/MULTI不可变草稿快照。Commerce→Case→契约/类型同步，历史兼容；不清库、不改金额上下文、不加模型权限。
2. 买家批次：统一商品卡片、去侧栏、列表/申请/详情层次和字号；异步商品读取有会话/页面隔离，失败独立可重试，申请仍可看。
3. 商家批次：列表/详情分离、商品图/金额、原材料/建议/操作可见，其余分层展开；保留原核验/人工方案/政策定位/审批门禁。
4. 集中验证：关联Java/Python契约及网页回归/build，真实HTTP只读商品/隔离，浏览器各主视图与桌面字号/溢出核对。优先现有终态数据与可明确区分的前端状态测试，不因截图造新收费调查或重置交易。每完成独立批次精确提交正常push，实际进度只记todo顶部。
