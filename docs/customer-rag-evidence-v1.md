# 客服RAG第四批：保留锚点的证据组装对照

2026-10-20用户批准接续。范围是固定Query检索后的证据组装与候选缺失归因，沿用第三批GPU结果和原始来源，不新增模型、服务或业务写入。当前进度只看tasks/todo.md顶部。

## 假设与边界

第三批Cross-Encoder让部分例外、适用范围与冲突依据退到Top5之外。检索子块是相关性入口，不能独立代表完整适用条件。本批复用现有`context_refs`、原受控父级绑定和源块表示：先保留直接命中的原文跨度，再在固定预算内补完整父级，拒绝半截父级，不让大父级挤掉已准入锚点。父级结构仍是原开发标注，物理完整不代表独立人工审核了语义适用性。

候选缺失P03/P06分别检查三路完整排名与固定窗口5/10/20；这些只是归因，不按标注给检索追加条款或直接调生产窗口。外部来源不作为商城退款政策；商城已返回完整权威规则，不给它套用外部章节父级。

## 冻结比较

数据为第三批原29问+18继承改写，各以相同的前3/5个检索锚点为入口，分组报告；原问题、Gold、原始HTML/子块、模型权重/版本与GPU排名不改。无独立holdout声明。

| 策略 | 锚点 | 证据组装 |
| --- | --- | --- |
| rrf-direct | 当前三路RRF | 仅原命中跨度，原文去重 |
| ce-direct | 原GPU候选并集精排 | 仅原命中跨度，原文去重 |
| rrf-parent | 同rrf-direct | 锚点优先，再完整父级 |
| ce-parent | 同ce-direct | 锚点优先，再完整父级 |
| dual-parent | RRF前K在前，再补CE前K中未重复项 | 锚点优先，再完整父级；最多2K锚点，单独披露输入量 |

每组使用同一个上限：原文正文8000字符及4096个项目本地DeepSeek tokenizer token，以较先达到者为准。预算在选择时使用，不裁切文本/条件。直接跨度和父级都按整体准入，超限明确记录阻塞；原文按source_id/raw_sha256/block_id/table_row/跨度合并，仅去除重叠。不同版本、来源、表格行与非相邻跨度不混同。

保存直接覆盖与组装后完整证据覆盖、相对RRF/CE的逐例改善/退化、候选和父级阻塞、原文/序列化token成本、组装耗时与packet hash。展开后的完整率称“证据包覆盖”，不能叫Recall@K提升。序列化包含来源/跨度/hash及正文一次；正文预算不是整个Agent请求的预算。两次重新组装应得到相同来源集合/hash，测量只含组装/本地分词，不含前置召回、GPU精排或答案生成。

## 验收和接入判断

- 原锚点已准入的跨度必须被保留，扩展不因预算删掉原命中；所有新增材料都来自已准入锚点的既有父级。
- 先用边界测试验证跨来源/版本、坏hash、原文被改、重叠/间隙/表格及预算；再冻结源码、来源和第三批报告hash，最后运行全部47问。
- 对ANSWERABLE题按17原问、12改写分别评分，其他题只留材料/成本，不将检索有输出当正确拒答。
- 不只看P09/P10；所有题的退化与成本必须一并报告。数据已用于开发，结果不能宣称泛化或最终回答准确率。
- 商城9条既有Query仅复核原完整规则的RRF/CE证据，不能把外部父级收益冒充线上商城收益。本批不自动上线CE或外部父级；需根据证据确定业务规则如何表达关联条件，再做Agent实际回答复测。
