# ResolveFlow v1.2：个人项目核心版

2026-09-18。用户已确认：目标是展示个人技术能力，不做公司级平台。本文件规定当前范围，优先于v1.1的必做清单。技术正确性不降级，但不追求商业流量、完整售后系统或通用Agent平台。

## 1. 唯一主链路

用户提出退款诉求 → Agent自主调查订单/物流与政策 → 缺证追问或转人工 → 形成有引用的方案 → Java复核及必要审批 → 模拟退款可靠执行 → 工单展示结果与调查轨迹。

核心处理物流异常与商品损坏退款；错漏发、补发、库存、退货入库不实现。用户单方损坏陈述必须人工核验，不开发图像识别。退款只支持一个订单行全部数量、原行实付金额、CNY整数分。不支持部分退款或历史混合售后。

## 2. 必做与非必做

| 能力 | 核心版必须交付 | 非核心：未经新授权不启动 |
| --- | --- | --- |
| Java | Gateway、Case、Commerce，独立业务库、鉴权、事务、索引与一项有证据的查询/缓存优化 | Fulfillment独立部署、库存、补发、跨动作权益Saga |
| 执行 | 退款幂等、金额预留、Outbox/inbox、UNKNOWN对账、旧授权拒绝 | 跨服务reserve/start/commit/release权益协议、执行中取消 |
| Agent | 单Agent动态决策、真实MCP、政策检索、有限追问、人工接管 | 多Agent、自进化、Skills市场、模型路由平台 |
| Harness | 分层上下文、预算/防循环、引用验证、调用记录、受限持久恢复 | 通用插件框架、任意版本热迁移、复杂任务调度平台 |
| 回放 | 选定完整合成轨迹的strict离线回放，明确不支持的记录 | counterfactual-recorded/world、合成世界回放器 |
| RAG | 商家/版本硬过滤、真实dense检索、BM25基线、引用校验 | hybrid/RRF/rerank全家桶、HNSW、四组强制消融 |
| 评测 | 一组固定workflow基线、核心Agent对比、代表性故障与安全测试 | 原240+60+120及每组3次的全量研究矩阵 |
| 展示 | 工单/审批/轨迹轻量界面，关联日志及有限指标 | 多角色完整管理后台、全套观测集群、商业级运营功能 |

缩减能力后必须缩减对应主张：不写“跨动作权益”“补发Saga”“反事实回放”或“生产高可用”。同一保留链路内的权限、资金和故障语义不能随意裁剪。

## 3. 部署与已有资产

目标为Gateway + Case + Commerce三个Java进程与一个Python Agent服务。Case/Commerce各自MySQL库，Agent用PG/checkpointer/pgvector，Redis用于非权威缓存或入口限流，RocketMQ用于退款命令/结果。继续使用已实测的版本锁，不重开T00版本选型。

物流作为Commerce内明确标识的模拟外部数据适配模块，不冒充真实承运商接口；不再维护独立履约数据库。退款provider-stub仍需持久化和可注入故障，但不计核心微服务。

Nacos、Sentinel及完整OTel/Prometheus/Grafana/Tempo不是核心交付门槛；保留已验证依赖，默认核心运行可用Compose DNS/显式服务地址，不依赖这些配套。不能为瘦身全量重搭脚手架。

已有fulfillment骨架、v1协议、fixture及测试保留为兼容资产，默认不部署，不据此宣传完成该能力。文档更新不等于代码已迁移。迁移由C00实施。

## 4. 当前事实与规范优先级

任务账本记录T00–T02完成；本轮未重做其测试或宣称完成业务功能。README等早期“从未实现”的说法不再适用。新任务C00起均待实施。

当前范围以本文件为准；业务/状态/Agent细节以当前专题文件为准。新协议目标见[核心契约](core-contracts.md)，现有[旧协议基线](contracts.md)和contracts根目录旧Schema是T02兼容基线，不代表当前所有端点都必须实现。C00先建立可机读的核心协议和选择清单，不允许靠关闭旧测试解决冲突。

[新任务账本](../tasks/todo.md)取代旧T03–T39必做顺序；旧记录保存在[todo归档](../tasks/archive/v1.1-todo.md)，仅用于追溯，不自动加入当前任务。

## 5. 核心完成标准

1. 用真实业务服务与持久退款stub完成自动退款和人工审核两条路径。
2. 相同诉求配不同证据可改变模型后续行动；没有隐藏的固定全量工具链。
3. 越权、重复退款、旧revision、UNKNOWN和worker崩溃均有可定位测试。
4. 有冻结的真实模型对照报告、成本/失败分母、少量strict回放包及一个查询性能对照。
5. 本地可重复启动，能讲清5个演示中的实现和取舍；每项简历主张关联代码与证据。

核心版通过即可称“核心版完成”，不必补齐延期项。目标是若干可深入解释的亮点，不承诺必须写满某个条数；不用减少测试断言来营造规模更小。
