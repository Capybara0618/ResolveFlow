# Agent 上下文与建议质量改进

2026-10-04，按用户批准实施。原则：模型每轮看到必要事实、缺口和政策条件；完整记录留在后台，避免重复进入请求。进度只维护在 `tasks/todo.md` 顶部。

## 本批范围

1. 固定合成诊断输入，保存改前实际 ContextPacket 与结论检查结果；不修改业务库或消费已有运行。
2. 消除已保护政策正文和已抽取事实在近期工具片段中的重复；不同版本、冲突来源、未知字段和政策例外保留。原始 Observation 不变、可按需读回。
3. 每轮明确工具读取/失败/未读及政策检索进展；读取成功不代表资格成立，NOT_FOUND 不代表未发货，空材料不代表客户主张不成立。
4. 拒绝建议要求真实事实及政策引用、已读取订单和物流/履约依据；不足时可继续调查、补证或转人工。保留退款原有校验与 Java 最终复核，不增加退款权限。
5. 同步 prompt、上下文/verifier manifest 版本；旧 run 不静默换规则恢复。定向验证循环、引用、实际模型请求、上下文、恢复和回放边界。

不进行模型生成式摘要、不删政策例外、不用评测答案选择上下文、不改 ABI 或用短引用替代冻结引用身份。本批不扩展检索组件。

## 输入、状态与输出

- 输入：系统绑定的工单/订单行/商家/客户/修订和政策范围、原始诉求、问答与人工结论。
- 状态：真实工具 Observation、带来源与版本的事实、读取进展、政策候选、预算和已确认动作。失败与未知不能当成否定事实。
- 模型动作：读业务、检索政策、读回原文、提出方案、追问或转人工；次序仍由模型选择。
- 输出：原协议建议/问题/人工原因及完整调查轨迹。结论检查不等于语义正确，也不等于 Java 批准。

## 验证方法

用固定输入比较原始实际请求的估算 token、政策正文出现次数及结论检查结果。诊断覆盖口语诉求、政策例外、多次检索、无命中、读取失败、不同来源冲突、同源更新和单方损坏。断言必要事实/例外/引用身份完整、未知字段仍可见、原文读回一致、拒绝依据不足被拦截。

这些是上下文与校验的离线工程证据，不能当作真实模型建议正确率或供应商计费 token。RAG 排名仍需用当前三店政策和新购物场景建立独立检索集；历史 40 查询仅是旧小语料基线。

## 后续依赖

先核实生产工具是否向模型提供明确履约状态和履约版本；现有物流 NOT_FOUND 不能推导 NOT_SHIPPED。随后按真实输入补全退款/拒绝的场景条件检查、关联政策例外与新场景召回评测，再有限验证固定版本真实模型建议。不得用提示词替代缺失的业务数据投影。
