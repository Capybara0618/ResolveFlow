# 原始政策文档与可追溯入库

2026-10-06，用户批准从原始文档补齐 RAG，暂不增加政策管理页面。现有生产政策、calibrated-v3、66条待审查询及历史报告保持冻结，采用追加的实验目录，不清数据库，不调用付费模型。

## 目标与边界

当前政策先被人工写成短规则，Python读取Java的规范JSON后索引；它没有证明复杂原文解析能力。新增链路：公开来源清单 → 保存原始HTML及抓取元信息 → 按明确正文范围解析 → 带位置的章节/段落/表格 → 人工确认的条款 → 原Java导入 → 原Python索引。原文、解析结果和业务政策是三种不同资产，不允许把公开材料自动映射到M-1001等演示商家。

首轮只处理静态HTML，复用Python标准库/现有锁，不做OCR、上传页面、爬虫平台、自动政策发布或新Agent循环。网页中发现的指令只能是文档内容，不能执行。无法解析、正文定位缺失、未知编码、跨行跨列表格暂不支持等情况明确标注；不把丢失结构的文本称为成功入库。

## 四批实施与产物

| 批次 | 内容 | 验收 |
|---|---|---|
| 1 | 规格、官方原文来源清单、抓取身份和版本边界 | URL经核验，来源/格式/结构风险明确；无商家采用或独立Gold主张 |
| 2 | 脚本保存原文件、严格解码、正文定位、章节/列表/表格及原文定位 | 合成结构失败测试＋实际网页解析；可回指原文件；异常不静默吞掉 |
| 3 | 新实验语料、待审条款、逐query必要依据标注和检索基线 | 与旧集分开；外部主体隔离；未审标签null；没有Gold就不计算准确率 |
| 4 | 按失败归因比较切分/表示/query/排序，再整体Agent对照 | 固定来源、标签和配置；改前改后同条件；不按案例编号写答案 |

## 原文样本

首轮4页、3个来源主体：京东服务总则与数码类目、小米有品自营售后规则、宜家电商使用条款。官方URL、编码、正文定位配置见[清单](../evals/policy-documents-v1/sources.json)。这不是4个独立商家上传，也不是4份已采用的商家政策。两份京东材料属于同一主体，后续开发/测试必须按来源家族分组，不能拆页冒充独立测试。

正文定位配置只负责找网页内容容器，不负责决定适用条款、退款动作或query；选择器可按页面维护，业务答案不可硬编码。宜家文件还包含非售后内容，先完整保留选中的文档结构，后续人工标注售后章节和无关材料，不用关键词删掉可能有关的例外。

## 保存与版本协议

- 原始网页保存在忽略的`tmp/policy-documents-v1`，不把整站HTML/外部版权全文推送到公开仓库；仓库保存来源、原文SHA-256及结构报告。本机原文件需保留或备份。URL不保证永远返回相同字节，重新抓取若hash变化视为新快照，不能复写已冻版本。
- 来源清单冻结采样身份，不以抓取日期冒充政策生效日期；未明确公布的生效日期为null。HTTP Last-Modified不能直接当政策版本。
- 单次解析绑定`source_id`、外部主体、原文hash、编码、定位配置和解析器版本。结果记录块ID、结构路径、原文行/列与字符区间，以及解析文本hash。字符区间针对解码后的原始文件，不是原始字节偏移。
- 标题/段落/列表项/表格分别存储；表格保留单元格位置和表头，不能只存拼接字符串。原文HTML保留备查；正文清理不修改原文件。
- 解析输出默认`PENDING_REVIEW`，不等于可执行政策或可引用Java规则。语义重复、冲突、章节关联和商家采用均须后续确认。

## 条款发布与检索衔接

后续确认条款时保留原文位置和条件/例外关联。短规则保持整条；长章节比较检索子段＋返回父章节/必要例外。必须测encoder实际token长度和截断，而不是用字符长度假定安全。生成现有Java导入格式之前校验业务范围、商家归属、引用血缘和采用记录；外部维修、换货、真实支付等只能作为参考/范围外材料，不能扩展核心可执行权限。

Java继续拥有政策权威版本和hash，Python仍通过`scripts/policy_index_ingest.py`读Java再建索引。索引表示改动生成新generation；不静默给旧run换manifest。实验检索可使用独立外部主体，但不得拿外部source_id伪装为生产商家引用。

## 评测与学习记录

先评解析：正文漏提取、表格关系丢失、条件/例外遗漏和定位可复现性。再评检索：前2/5必要依据覆盖、多依据找齐、相似但不适用、无答案、错主体/版本。最后评Agent事实适用与建议质量。模型query、合成问法、公开FAQ和真实客户日志分别标记，Agent生成标签只作草稿，独立审查为0时如实报告。

不为凑文档数量编造规则；初始4页是实现探针，不是充分的真实分布或正式检索质量证明。重要失败记录现象、根因、通用处理、验证与局限。唯一执行进度位于[todo顶部](../tasks/todo.md)，实际命令及未运行项进入集中报告。

## 结构准备的实施约定

原文来源和第一版解析冻结后，新的正文定位/章节解释放进独立[结构草稿](../evals/policy-structure-v1/README.md)，不改旧source hash或伪造政策生效日期。正文选择器是页面布局适配，hash绑定的标题/表头/关联是可复核的文档结构标注；通用构建脚本不认识退款场景编号、query或最终动作。

草稿检索表示与完整依据分别记录块引用和hash。附注/排除条件作为候选关联保留，章节覆盖校验确保正文块不遗漏或重复归属；关系闭包必须有界。Codex结构判断明确标记，不能成为独立人工Gold或商家采用记录。最终发布和索引仍须确认内容、来源、范围和版本。

章节长度用固定本地embedding tokenizer测，包括特殊token，不截断。超限候选标requires_split；后续拆检索子块，保留父节/必要例外定位，不把大章节直接交给encoder截断。完整依据同样不能无界注入LLM，后续须按事实/相关性和上下文预算验证。长度安全、解析结构正确和语义适用是三个不同门槛。


## 检索子块与完整依据（2026-10-06）

离线脚本`scripts/policy_chunks.py`读取已冻章节草稿及其报告，校验草稿字节、解析器/构建器/来源/结构manifest指纹后构建子块。每个原文块仅从直接所属章节生成一次，父节完整内容保留为context，不把整篇重复作为检索候选。章节内部按原段落顺序聚合，长段落按固定encoder tokenizer的真实token/offset切分，优先靠近句界，特殊token计入；每个最终字符串再核对token长度。384是本次候选配置，尚未证明最优，encoder实际上限512不可被配置绕过。

子块保留source_id/subject/raw_sha256、章节路径/context_id、原块定位和hash、表示字符区间/片段hash。普通段落连续区间无丢失无重叠；这里的表示区间不是原始HTML字节区间，原文位置另存block_locator。简单表格将每行表示为列名与值，保留行号及整表定位；合并表格只保留原单元格并标grid_requires_review，不伪造逻辑网格。子块独立编码可能丢失章节标题语义、长表格行拆分也可能弱化列关系，须在下一步检索失败归因中验证，而非声称长度安全即语义充分。

命中子块后通过`complete_context(bundle, chunk_id, max_chars)`回查已保存的完整章节及候选关联；主体/快照/hash不一致拒绝。超过字符上限返回CONTEXT_TOO_LARGE、complete=false、text=null，仍保留必需块引用，不截一部分冒充完整政策。此导出字符上限不是模型token预算，也不是生产Harness的限制；接入LLM之前仍须按LLM tokenizer计算、去重、必要性选择并检查例外保留。关系来自待审结构草稿，不能保证语义上已找齐所有例外。

```powershell
# 输出路径必须是新文件；本地模型需已按项目既有方式准备。
agent/.venv/Scripts/python.exe scripts/policy_chunks.py --max-tokens 384 --embed --output tmp/policy-documents-v1/children-new.json
```

不带`--embed`仅构建及审计长度；带该参数使用既有本地BGE生成实验向量，检查数量/维度/有限非零。不写PG/Java，不改变生产索引，原文全文/完整依据/向量只存忽略缓存。子块仍PENDING_HUMAN_REVIEW、publishable=false、indexable=false；有实验向量不等于获准进入生产。原文、结构配置、切分器或参数变化均应生成新快照，严禁覆盖旧输出。

本次66子块/29完整依据、实际向量与4条合成查询接线探针见[报告](../reports/policy-document-ingestion/README.md)。接下来冻结逐query所需依据与无答案/相似不适用样本，独立复核后比较召回和完整依据覆盖；先评价失败再决定标题表示、混合检索或重排，不能凭4条接线探针宣称RAG优化成功。


## 逐query基线与复核（2026-10-06）

[新逐query包](../evals/policy-query-v1/README.md)追加29问/41来源依据原子，复用11官方FAQ并新增18合成结构诊断；三个来源家族不拆页制造holdout。query、draft和独立review分开，所有review尚待审。依据绑原文block/表格row/span与来源/hash，不绑定某个算法的chunk ID或排名。原文和基线字节均冻结；独立确认或实验参数变化新建版本，不改旧标签刷新分数。

离线入口`scripts/policy_query_eval.py`可生成隐藏标签/排名的全来源复核包，也可运行同条件dense/BM25前2/5诊断；另有require-reviewed质量门禁，未独立标注则明确失败。评分区分直接字符区间覆盖和成功导出的完整父节覆盖，去重并限制所有context合计字符量，不把被拒导出的依据算命中。非可答问题不空集合刷通过；拒答需要后续判断层，单纯返回近邻无法证明接受了无答案。

当前报告显示扩展后覆盖明显高于直接覆盖且带回数千字，提示检索与上下文装配须分开归因；标签同作者，不能用这些诊断挑生产算法。正式质量指标null，下一步先复核必要依据/例外/适用性，再在冻结标签/语料/query条件下比较表示或query策略。详见[集中证据](../reports/policy-document-ingestion/README.md)。


## 表示与装配的实验边界（2026-10-06）

[policy-representation-v1](../evals/policy-representation-v1/README.md)固定query/evidence/旧baseline和依赖，在复现旧排名后比较body与完整章节路径、完整context与来源块并集。22通用测试和真实本地embedding证明子块长度安全、来源块无损准入与预算拒绝；不改Java政策/生产索引，不增加LLM调用。

完整标题路径在草稿dense前5退化，保留失败、不采用；“加标题通常有效”不能代替本项目测量。来源块去重减少本轮平均体积，但释放空间也可准入更多无关context，且贪心算法不能保证普遍不丢后续证据。下一步把依据选择与表达分开：先确定真正需要的context/条件/例外集合，再无损去重，并按聊天模型token与引用包装验证。当前字符实验不是完整Agent上下文优化，也不能代替独立标注。


## 固定选择与证据包 token（2026-10-06）

[policy-context-packet-v1](../evals/policy-context-packet-v1/README.md)把上一批的选择和表达拆开：复现旧整context的贪心准入，固定context IDs、来源块及指纹，然后无损去重。释放空间不再新增章节；通用反例证明后续context不会因为表达变化被替换。选择器不看query内容或Gold，来源/快照/原文与引用映射在选择后仍须校验。

正文和完整引用JSON均用既有DeepSeek V4.1 tokenizer离线测量，不再拿字符等同模型token。两表达携带同样的网址、快照hash、块hash/定位和context映射；116前缀无源块丢失、新增或正文增长，但完整溯源字段占据大量token。前5正文token均值dense减少16.71%、BM25减少18.31%；含完整溯源的实验包仅减少3.36%/3.54%，不建议整包注入模型。旧生产上下文未改；本地证据包计数也不等于完整Agent请求或供应商计费。

取舍：系统保留完整原文、版本、定位与hash；模型应只读取必要正文、短引用和必要的适用信息，通过受控回查解析完整来源。下一步另冻短引用实验，证明短引用可回查、跨主体/快照不可混用、来源变化可检出，再考虑接入生产，不能通过删掉系统溯源来刷token指标。当前独立人审0、正式质量null，不宣称相关性或回答质量改善；结果和实际命令见[报告](../reports/policy-document-ingestion/README.md)。
