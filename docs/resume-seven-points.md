## 项目介绍

**ResolveFlow｜基于微服务与 Agent 的电商智能售后平台｜个人项目**

面向多商家售后场景，贯通购物、退款申请、Agent 调查、人工审批与模拟退款执行。Agent 根据订单、物流和政策证据动态选择调查动作并生成建议，Java 服务负责业务状态、版本化授权与资金约束，提供工单及调查轨迹展示。

技术栈：Python、FastAPI、AgentScope、MCP、PostgreSQL/pgvector、BGE、RAG；Java、Spring Boot、Spring Cloud Gateway、MyBatis、MySQL、Redis、RocketMQ、Vue 3、TypeScript、Docker。

## 七条正文

1. **多租户电商微服务**：采用 Gateway、Case、Commerce 与 Python Agent 四服务架构，通过 RocketMQ 与 HTTP 协作；实现商家数据与权限隔离、平台买家跨店购物，使用乐观锁及行级锁处理购物车并发与金额一致性，支持单店多行订单原子发布和逐行独立退款。

2. **Agent 自主决策**：基于 AgentScope 与 MCP 构建观察驱动的调查循环，动态选择工具、追问材料及生成建议；在【N】个场景的同条件对照中，相较固定调查流程，建议准确率【A】%，复杂场景有效处理率提升【B】个百分点，平均模型调用【C】次。

3. **政策检索与 RAG**：基于 BGE 与 pgvector 检索政策，绑定订单付款时刻的适用版本并过滤商家与品类；对外部原始政策文档开展关键词、向量、融合及重排五组对照，采用【最终方案】，Top-3 召回率【A】%，较 BM25 提升【B】个百分点，平均检索【T】ms，并完成商城政策验证。

4. **版本化授权控制**：通过 input_revision 使补证或人工核验后的旧方案失效并触发新调查；Agent 仅建议，Java 管理授权与预留，审批及消费均复核版本。在【N】组并发竞争场景中，过期授权拦截率【A】%，有效授权通过【n/M】。

5. **分布式可靠退款**：通过 RocketMQ、Outbox/Inbox、操作幂等与金额预留处理消息重投和并发退款；超时保持 UNKNOWN 并按原操作对账。在【N】次故障试验中，重复退款【D】笔、超额退款【E】笔，UNKNOWN 收敛【n/M】。

6. **Agent Harness 防护**：统一调用预算、工具白名单及 schema/引用校验，以错误反馈驱动有限纠错并防止循环；通过数据库租约、fence 与持久快照恢复运行。在【N】次恢复对照中，复用已落库响应减少重复模型请求【X】次，新增 token 用量降低【A】%，strict 离线回放【m/M】包匹配。

7. **Redis 缓存与限流**：为审核队列建立复合索引与游标分页，采用 Redis 短期缓存及 Semaphore 有界回源；在 2 万工单、【N】并发下，接口 p95 由【A】降至【B】ms，数据库查询量降低【C】%；Redis 故障时回源并发峰值不超过【K】。

占位表示待测。结果句可以按实验改成前后值、计数、覆盖率或单项实现结果；不要求每条都有提升，也不强制把全部收集指标写入成稿。第 3 条最终技术路线由候选比较选定。

建议准确率按动作、事实、适用政策及补证责任逐例评定；复杂场景在运行前分类。两组的检索 query 使用同一模型，固定流程按预设次序调查，动态 Agent 按 Observation 选择行动。评分由 Codex 按实际输入和完整轨迹复核，无新增用户人工标签步骤。

RAG 先比较候选，随后两组 Agent 共用选定检索方案。RRF 融合召回排名，再执行 rerank。Recall@3 为必需条款的覆盖比例，完整依据命中率@3 为前三找齐全部必需条款的查询比例；MRR 衡量首个相关条款的排名。检索耗时包含 query 编码、实际召回、融合及重排，不含首次模型下载/加载。外部与商城结果分别报告。

恢复请求减少量按「从头执行新增请求−持久恢复新增请求」统计；输入与输出 token 分开留原始 usage，再汇总差异。每个窗口分别统计，strict 匹配与恢复收益独立报告。

本轮先完成文案与执行计划，未启动新实验或新增模型调用。执行计划已经明确8类授权/6类退款/3个恢复窗口及统计口径，后续按批次补执行器与测量；最终结果直接更新本文件。
