## 实施边界

1. 统一计量：最终消息序列化加一次包装预留，输入上限以包含包装的同一口径计算；单步上限8192、输出预留、累计预算仍生效，不把字节估算宣称为真实token。更新计量/上下文版本，新运行采用新版本，旧run不静默替换manifest。
2. 固定说明去重：保留职责、动作字段/枚举、引用格式、读取界限；重复引用/权限解释归并，不修改动作ABI或执行安全检查。
3. 按来源组织事实：同一Observation的完整引用/权威属性展示一次，再列精确字段、状态与冲突说明；保护hash按原始facts计算，不因展示分组改值。核验沿用已完成的真实order_status/旧status映射，不重复迁移。
4. 材料正文有界呈现：短文原样，长文保留首尾预览、总长及当前run/revision的真实读回位置。所有材料身份、问答关系、人工结论仍保留。材料读回不是新的业务权威证据，不能用材料ID或本地读取结果替代get_case_evidence外层引用。
5. 每轮重建：当前有效事实与冲突保留，最近动作有界，较早工具内容转索引；长文页按需读取。沿用已有去重/政策保护/索引机制，不再实现一套SDK memory或额外LLM摘要。

原文索引必须可实际读取。复用本地READ_OBSERVATION入口，以material:材料ID定位派发快照的正文；该索引仅在当前run绑定的revision中可用，原文重建来自持久review_context，恢复无需网络。缺记录/越界/未来版本明确失败，不能猜测、升级用户陈述或放松Java最后复核。
