# 客服Agent答复状态、事项状态与原句定位修复

2026-10-22，按用户修复授权处理experience-v2的已确认根因。不重跑收费实验或简历指标，不重构SDK/Java权限/RAG召回。分三个独立小步，逐步测试、精确commit普通push。

## A 原句定位

模型仍提供reference/quote，可省略offset。程序只在同一个合法客户消息内查找完全相同的Unicode原句：唯一匹配时保存程序计算的位置；即使模型位置不准也使用唯一实际位置，原始模型决定仍不改。重复原句必须提供确实匹配的位置，否则明确歧义；不存在、助手/未来/未知消息、用历史原文冒充当前事件仍拒绝。不做模糊匹配、Unicode归一化或跨消息猜来源。

## B 生命周期

保留status作为本轮处理/答复状态；新增只在需要持久/继承时使用的lifecycle=OPEN/PAUSED/RESOLVED/CANCELLED。ANSWERED不关闭事项，程序按显式且有客户原文的事件更新：ADD/CONTINUE/CORRECT/CLARIFY保持开放，PAUSE暂停，RESUME恢复，CANCEL撤回，新增RESOLVE明确结束、REOPEN再次讨论。模型选择事件，程序维护状态，不通过用户关键词自动改状态。

旧状态读取兼容：CANCELLED映射撤回、SUSPENDED映射暂停，其他（含ANSWERED）视为仍可讨论，不更写历史数据。最近成功答复中的已答事项可再暂停/纠正/撤回；未完成事项继续必须覆盖，已答FAQ允许本轮不携带，原历史保留，不扩成无限主题平台。前轮明确RESOLVED/CANCELLED的事项不能通过普通CONTINUE静默恢复，须REOPEN及当前原文。业务核查单、退款或物流是否完成仍由Java/实际来源决定。

生命周期放入最终task_state.tasks便于现有Java透传，不新增数据库迁移；previous_hint只继承状态/诉求，不继承旧O/P引用。原始决定保存不改、带fence重放须结果和请求相同；旧run/旧清单不静默换版本。取消/暂停仍需对应状态，不能静默删除未完成任务或补造当前事件。新增enum/序列化涉及的生产者与测试同步。

## C 事实表达

对已读订单/物流添加小型、带来源版本的语义字段视图：明确订单行状态与承运结论，不把多个同名status合成一个状态。原始来源/条件/失败/不同版本继续保留，不从PAID推断运输、不从NOT_FOUND推断未发货。视图只是确定性字段投影，不能证明模型每句都正确，也不加按题号/问法匹配的修补或额外LLM。
