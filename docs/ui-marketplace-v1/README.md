## 图文交互合同

- M01/M02商品→M04；店铺名→M03；M03可返回全站商城。商品只展示公开字段，跨店浏览不扩大私有数据权限。
- M04数量可调整，服务端限制有效范围；“立即购买”和购物车结算共用报价、草稿、支付与订单发布协议。商品上架、规格、价格和允许动作由服务器复核。
- M05可以保存多店商品。每店有明确结算按钮，只提交本店选中行；其他店条目保持。实施时价格列明确标为“单价/数量/小计”，不做跨店全选付款。
- M06单店一次结算多行，服务端金额整数分；合成地址区域不是任意修改客户身份的入口。点击提交成功后进入M07；重复请求重放同草稿，价格变化先确认新报价。
- M07成功后只能查看已发布订单，不能再次付款。取消只用于未支付草稿；期限和支付/取消胜负由服务器判断。付款成功事务同时发布原订单、各行、账本和退款槽；响应未知只查询原尝试，不自动建立新尝试。
- M08同一已认证平台买家汇集本人在两店的订单，支持店铺与状态筛选。待支付草稿“去支付/取消”，已付订单看详情和具体行退款资格；整单卡上的申请入口进入行选择，不能暗示整单无条件退款。
- M09每行展示自己的实付、资格和申请状态。耳机329元正在审核不影响键盘398元的显示；能否继续申请须先补多行资格规格。支付、物流和售后分开，申请表/补证/结果继续使用已有客户工作台。
- 已付未发货“申请退款”是目标新增能力，正式实施前必须补政策/资格并验证，不假装当前物流政策已覆盖；仍由人工审批、原资金执行，不把取消订单当成直接退款。
- M10/M11限定已认证管理员所属商家，不提供私有跨店切换。首次模拟发货产生持久轨迹及版本，发布后不可随意改模板或原事件；没有交易页直接批准退款按钮。发货写权限不替代售后负责人权限。
- M12价格更新重新确认、下架返回商城、明确失败才允许新付款、到期重新购买。重复提交显示/禁用提交并查原结果；若取消/支付竞争，以服务端胜出状态跳转。图未单独画这两个中间态，不代表省略它们。
- M13非本人/非本商家订单不泄露细节；无申请展示入口，有活跃申请查看原申请，已成功行不再申请。UNKNOWN等待原退款操作结果，保留同operation和预留，禁止新建操作重付。
- 售后专员继续看原始材料、Agent/RAG证据及建议，然后人工操作；买家页不展示内部推断、授权细节或其他买家订单。商家管理员不能维护全平台买家的密码/启停。

## 视觉规范

采用熟悉的商城搜索、分类、商品和个人中心结构，延续ResolveFlow白蓝品牌。购物浏览区无后台管理侧栏；个人中心可有“我的订单/我的售后”侧栏，商家工作区保留管理导航。商家侧导航具体路由继续对照已有工作台，不因图里简称删去公共队列、我的工单、需关注、历史查询等已有入口。

生成要求：1536×1024横向画布，正文24px、次要字22px、标题36px、价格32px的意图；这是提示要求，不是自动测量证明。实际图册按原图查看可读层级，正式CSS采用正文16–18px、关键内容不低于16px，并在1280/1440/1680验证。长编号/版本/hash放展开详情，不加角落说明、版权脚注、营销标签或虚构库存/销量/好评率。

模拟环境在页头清楚标识，付款与物流仍保留必要的模拟标记；不以删事实换留白。品牌、边距和图片造型在位图中有轻微差别，实施时统一组件和SKU资产，不逐像素复制生成图。
