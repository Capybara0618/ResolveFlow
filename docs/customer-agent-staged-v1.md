# 客服Agent职责拆分试验v1

2026-10-22，用户批准尝试新架构。目标是修正experience-v3已证实的状态/协议缺陷，并验证同模型职责拆分的工程可行性；本批只做离线与脚本模型/真实隔离PG验证，不新增收费调用、部署或改简历。生产唯一循环仍由AgentScope 2.0.8驱动，不增多Agent/框架/模型依赖，不改RAG排序或Java资金权限。

## A 公共事项基础

当前task_state.tasks既是当轮答复清单又被Java作为前轮事项传递，漏列导致事项消失。将发布的task_state定义为有界会话事项快照，tasks保存已接纳的事项，focus_ids明确本轮答复覆盖集合。本轮TaskTracker仍验证答复覆盖自己的tasks，DialogueState保留未提及事项及原生命周期，不从漏列推断暂停/结束。事件可以更新未在本轮答复中展开的旧事项；事件须有当前客户原句，新增事项仍须声明。再次讨论原事项使用相同ID，新建与旧事项语义是否相同仍需理解模块判断，不宣称规则能判断全部语义。

快照沿用Java现有MODEL任务透传，无DB迁移；只继承id/intent/request/答复状态/lifecycle/阻碍，不继承旧O/P和答复原句。首次旧previous_tasks兼容；最多8事项，超出明确失败，不暗删未结束事项。闭合事项继续保留供显式重开，容量扩展后续再定。最终快照必须可从保存模型决定重建；旧run不能换manifest恢复。隐私/商家/订单行的上游冻结及Java透传不变。

## B 输出接口减负

事件决定事项生命周期；模型不再靠两个枚举共同表达暂停或结束。旧ANSWER/ANSWER_PARTS保持解析兼容，针对明确PAUSE/CANCEL/RESOLVE事件由程序派生对应展示状态（SUSPENDED/CANCELLED/ANSWERED），保存原始决定不改，派生快照可观察；事件quote、合法前态和任务ID仍校验。未提供事件的取消/暂停仍拒绝，未明确重开的结束事项仍不能恢复。

READ_TOOL允许可选purpose说明（限长、非执行参数），统一原工具目录用途说明与调用接口；仅tool_name/arguments影响执行，主体/参数/工具白名单及其他未知字段仍严格校验，不靠扩大重试掩盖错误。

## C 分阶段试验（显式可选，默认公共基础单Agent）

同一AgentScope循环、同一模型/预算/调用账内先理解本轮再调查与答复，不在SDK外新增模型循环。新增TURN_UNDERSTANDING动作，仅声明本轮焦点事项、当前客户原句事件和记忆变化；不查工具、不写客服答复、不输出生命周期或本轮答复结果。程序应用变化、维护事项状态并锁定本轮焦点。后续模型自主选择工具，最终只输出分项答复，不能重写理解结果/事项清单；需要澄清可作为理解结果对应的答复，不能在调查阶段静默增删任务。权限、窗口、deadline、一次纠错与fence覆盖所有阶段；分阶段理解也计模型调用，不宣称减少调用。

理解提示只展示问题/历史、事项与客户陈述；调查答复提示只展示本轮焦点、证据和工具，避免反复要求生成事件/记忆标注。通过SDK工具确认动作转入调查，按需读回历史，模型仍动态选择调查顺序。完成检查对声明的本轮依据需求逐项验证：物流事实、政策资格、平台流程，混合需求可并存；不能仅用主intent绕过指南。规则不宣称验证全部自然语言事实，错误需求标注仍需真实源审。
