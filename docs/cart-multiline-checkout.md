# 按店购物车与多行结算

2026-10-03，第四批M05/M06的正式实施规格。范围沿用[六批路线](marketplace-implementation.md)，前三批目录、平台买家和付款恢复复用，实际完成状态只看[todo顶部](../tasks/todo.md)。本文件规定本批行为，不表示购物车或多行付款已经实现。

## 先完成行级资金规则

每次退款仍仅一个订单行的全部数量、原行实付金额。整单支付账本保存实付/已退/预留，不能把整单已退金额直接从每行实付扣除。新增核心LineContext可选事实order_paid_amount和line_refund_state；原refunded_amount/reserved_refund_amount保留整单含义。当前Commerce必须返回真实整单实付及本行槽，Case计算：本行FREE时，可退额=min(本行实付，整单实付−整单已退−整单预留)；RESERVED、CONSUMED、缺槽/缺账本或不一致事实为0。旧响应不含新增字段时保留原保守算法，不能把未观察到的槽当FREE。客户资格、方案复核和审批统一用同一个计算方法；最终接受退款仍在Commerce锁内复核金额/数量/槽与整单上限。

一行已退不妨碍另一FREE行；一行UNKNOWN保持原operation及占用，但另一行在整单剩余额度足够时可处理。同一行至多一次成功；整单已退+预留不超过实付。资金写入锁序统一整单账本→本行槽；结算先锁账本、重读操作再判断是否已终态，重复结算不多扣钱或多发事件。外部provider不放入这些事务。退款状态单独投影NONE/IN_PROGRESS/PARTIALLY_REFUNDED/REFUNDED，PAID仍表示付款事实，不将部分退款当作整单未支付或全退；履约与退款独立，不新增伪物流。

Agent退款只读视图追加order_paid_amount、line_refunded_amount、line_reserved_refund_amount。旧两个金额成员仍为整单合计，新增本行金额由真实槽与整行全额约束投影。上下文明确区分本行与整单，不能把其他行已退当本行已退；来源/版本/hash保留。Agent仍不获得付款、审批、跨主体或政策修改权限。旧兼容Schema/fixture不改，core协议追加成员。

## 持久购物车

Commerce拥有按可信(merchant,customer)归属的购物车，Case只允许当前平台买家，按持久BuyerScopes组合自己的店铺，不接受自报customer。购物车每个SKU一条，稳定版本用于增删改的并发检查，数量1至服务端max_quantity，每店最多20个SKU。重复加入由显式目标数量和原请求键处理，网络未知不能换键盲目再加。其他买家同SKU不共享条目。

读取展示当前公开商品/规格/单价/数量/小计，保存加入时观察的SKU版本用于提示改价；下架、数量超限或店铺停用保留条目并标明原因，用户可删除。不能静默删除或用旧价格结算。按店选行；不提供跨店总额付款按钮，另一店条目始终保留。

## 报价与草稿

单店多SKU报价按sku_id排序规范化，拒绝重复SKU、空集合、超过20行、混店、非法数量或失效归属。服务端返回每行商品/规格/单价/数量/小计及SKU版本、整单合计；CNY整数分，金额乘加精确，整单上限沿用核心AmountMinor的1,000,000,000分，各行之和不能超出。提交携带每行sku_id/quantity/expected_sku_version及原Idempotency-Key，不接受单价、合计、主体或付款结果。

提交重新锁住价格/上下架权威并核对版本，改价409要求重新报价；同键相同规范化行集合重放同草稿，下架/过期后仍能找回，同键异请求409。直接购买与购物车采用同一草稿/支付事实，保留既有单SKUAPI及已持久草稿；只追加迁移，不修改V10/V11。草稿保存不可变行快照，15分钟到期，待付无已支付订单/槽/账本。

本店已提交的选中条目在草稿创建同一事务中按所观察购物车版本移除；提交时版本不符拒绝并保留全部条目，不能删除用户后来编辑的内容。其他店/未选行保留。重复请求只回原草稿，不能再次清空新加入商品；付款失败/取消不自动恢复购物车，用户显式重新购买。

## 多行付款发布

继续原短事务reserve→事务外持久模拟收据→原子settle。每个草稿一个固定总额支付尝试，发布一个orders及总额payment_ledger，每个快照行一个稳定line_id和FREE槽，成功收据时间作为全部paid_at。行ID在尝试前固定，UNKNOWN/响应丢失/发布中断沿原attempt恢复；任一行写失败整批回滚，不允许半单。新读取返回全部真实行，旧单行成员只作兼容，不借它省略其他行。取消、到期、确定失败再付和原键规则沿用[第三批规格](simulated-checkout-payment.md)。

M04加入购物车；M05每店单价/数量/小计、选行与独立结算；M06展示本店全部行与报价；M07–M09复用多行付款及本人订单，每行售后入口读当前资格。主事实16–18px，内部编号折叠。加载/空/错/冲突/改价/下架/未知如实显示；旧回调不能覆盖新路由/账号，不自动重复写入。
