# Harness 纠错闭环（2026-10-05）

本批按用户要求补现有单 Agent 的纠错与恢复，不重建 RAG、Gold 或业务数据。AgentScope 2.0.8 仍是唯一生产循环，Java 仍拥有审批和资金权限。

## 闭环

模型响应 → 结构/动作权限校验 → 执行已批准的只读工具 → 工具响应契约/主体校验 → 更新事实 → 建议引用/关键事实一致性校验 → 成功建议或安全交接。

校验错误以短反馈进入下一轮 P1，包含错误类别、字段/来源、下一步和剩余纠错机会；不把错误原文当事实，不向上下文重复灌入整份失败响应。原始模型响应、工具失败 Observation、请求/用量继续进入现有持久日志。

## 本批边界

- 模型输出不是 JSON：记录原输出为不可执行响应，实际 usage 照常结算，由动作门禁给一次修正机会；HTTP 鉴权错误仍不能通过改 JSON 修复。
- 模型动作/引用/关键事实错误：同一个 run 共用一次修正机会；第二次失败停止。修正也是正常、计数的模型调用，不另设隐藏循环。
- 五个 MCP 的原始业务响应：复用当前 core OpenAPI 响应组件检查类型、必填、枚举、日期、版本及绑定订单行/工单；在截取/分页前检查，失败无可引用 hash/version。修正商家服务数据不是模型的权限。
- 临时工具读取故障：错误进入持久 Observation，下一轮可选择重读同一工具或换调查方向。同一工具最多两次连续临时失败，之后不再执行重读；读到成功重置连续失败次数。结构错误、缺失等非临时失败不能盲目重读；FORBIDDEN、主体错配直接停止。无效 cursor 是模型参数问题，共用一次修正机会，用已发出的 cursor 或省略参数，不换主体。
- 关键文字事实：检查本项目的履约、承运商确认、实付金额、退款完成等明确断言与当前成功且已引用来源是否一致；建议/条件/客户陈述与已确认事实分开。金额区分订单行和整单，整数分与元按100换算；新失败不能被旧成功遮蔽。summary 与 review_findings 都检查，finding 还限定自己的引用集合。该确定性检查只覆盖代码列出的有限表达模式，不等于通用自然语言事实证明，也不能证明客户图片的真实性；其他改写、潜在矛盾仍需评测与人工复核。当前退款状态工具提供槽状态，CONSUMED 本身不证明到账，不能据此宣称退款成功。
- 恢复：从已保存响应重建门禁反馈、纠错次数和工具失败记录，不重置预算/deadline，不重新调用已落库的模型/工具结果；来源及 manifest 不兼容明确失败。
- 人工交接：纠错耗尽、权限问题、关键事实无法支持时给失败原因；不输出已验证退款建议，不进行退款。人工可以在现有商家工作台复查/补证/重新发起调查。

## 集中验证要求

先失败测试覆盖：非 JSON 后修正、连续错误终止、字段类型/枚举/缺失/主体错配、失败不可引用、临时失败后成功、不可重试失败、建议与 LOST 来源矛盾、虚构退款完成、正常建议/否定/条件语句不误杀。

运行现有 SDK、MCP、持久恢复/fence、callback 和上下文回归；崩溃窗口验证反馈只恢复一次、已落库失败不重发、纠错机会不重置。源代码变更后独立冻结新回放 profile，旧回放与 Gold 保留。报告区分离线模拟、真实 MCP/PG 与真实 LLM；没有真实 LLM 结果不得宣称建议准确率提升。

## 已实现的代码边界

| 边界 | 实现 |
|---|---|
| 输出格式 | `harness/live_model.py` 保存非 JSON 原输出为不可执行记录，正常返回 usage；`sdk_runner.py` 分类并修正 |
| 短反馈/有界纠错 | `harness/correction.py`、`ActionGateMiddleware`；FORMAT / ACTION / SOURCE / FACT / TRANSIENT / TOOL_DATA / PERMISSION |
| 五 MCP 返回 | `tools/result_validation.py` 复用 core 五个响应组件；`catalog.py` 在原始读取后、分页/截取前校验；`mcp_client.py` 再验协议、来源类型/路径、主体和 revision |
| 建议后置校验 | `harness/claim_checks.py` + `verifier.py`；SDK 与最终 callback 同校验，未通过不得发布已验证建议 |
| 失败持久/恢复 | `runtime/durable.py` 记录可重放错误 Observation；修正协议禁止的 null 写法；P3 字段提示排序确定化，避免 PG JSON 键顺序影响恢复请求 hash |
| 最终轨迹 | `runtime/worker.py` 在原 fence/回调事务内保存 no_progress 计数；`replay/export.py` 用当前读门禁区分模型请求与实际执行 |

纠错“经验”是当前 run 的短错误反馈，由已落库响应与 Observation 重建；没有自动把模型反思写成跨工单长期规则或修改政策。未知编程错误、凭据获取失败、fence/deadline 冲突不会变成可重试事实。
