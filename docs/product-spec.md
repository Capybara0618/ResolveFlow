# 产品与业务规格

版本：1.1。状态：框架基线；下述金额和时间是本项目虚构商家政策，不是法律或平台规则。v1.1深化Agent Harness，不扩大售后业务范围或交易权限。

## 1. 已确认目标

个人独立工程项目，服务于2026年12月前后的实习求职。Java与Python均有完整实现，最终能演示、压测、注入故障并复现Agent效果。无需商用用户。开发投入未精确承诺，不以估计周数替代验收。

## 2. 角色与操作

| 角色 | 范围 | 操作 |
| --- | --- | --- |
| CUSTOMER | 本人的订单和工单 | 提交诉求、选择期望方案、补充材料、查看进度、提交前撤销 |
| REVIEWER | 分配商家内的工单 | 阅读证据、批准/驳回方案、请求补充、形成新的人工方案 |
| OPERATOR | 指定商家运维范围 | 查询异常操作、触发安全重试/对账，不可直接改账 |
| POLICY_ADMIN | 指定商家 | 导入及发布样例政策；不能审批自己的政策外例外 |
| AGENT_WORKER | 单个已分配case/run | 读取授权数据、提交问题/方案；不可执行业务动作 |

演示包含2个商家、每商家2个消费者及2位工作人员，用于越权和跨商家检索测试。权限设计是真实实现；不实现租户计费、商家入驻或完整IAM产品。

## 3. 明确范围

- 一个工单对应一个订单行，处理该行全部数量。订单行金额是下单时分摊优惠后的实付金额，币种固定CNY、整数分。
- 用户提交时选择期望方案 REFUND / RESHIP / EITHER。自动执行只能在该集合内；改变方案要新确认。
- REFUND全额退该行尚可退的原始行实付金额；已有部分退款/混合权益历史的行不在自动范围，转人工。
- RESHIP补发原SKU与原数量到订单原地址；变更地址、替代SKU、二次补救均转人工，v1不执行。
- 已成功退款或成功补发的订单行不能再次自动或人工批准第二次执行；人工可记录线下处理结论，不得绕过权益约束。
- 模拟支付/物流承运商由有持久状态的stub实现，提供幂等键、状态查询和故障模式。
- 商品损坏材料只做文字陈述、受控证据记录和人工核验；不做OCR/图片真假识别。界面不声称自动鉴定损坏。

## 4. 固定三类场景

| 编号 | 场景 | 必须证据 | 建议与分流 |
| --- | --- | --- | --- |
| SC-L | 物流异常 | 订单支付、物流轨迹、承运商结论、用户诉求、适用政策 | 72小时未更新可提出调查，不能仅凭此退款；确认丢件可申请退款/补发；签收未收到必须人工核验 |
| SC-D | 商品损坏 | 订单、签收时间、用户材料、人工核验证据、政策 | 签收7日内进入损坏审核；未核验材料追问/人工；核验后形成新方案并重新授权 |
| SC-W | 错发/少发/漏发 | 订单行、仓库发货清单、SKU/数量差异、用户诉求、政策 | 权威仓库清单确认差异且其他条件满足可低风险处理；仅用户陈述须补证或人工 |

其他问题如退货无理由、价格保护、优惠拆分、跨境、欺诈判定统一 MANUAL_REVIEW，保留原因。异常证据为不可覆盖记录，后续版本可纠正旧结论。

## 5. 低风险自动执行门槛

所有条件同时成立才可自动授权：

1. 订单属于当前消费者/商家，已支付；该行没有既往成功补救或其他权益占用。
2. 方案动作在用户确认的集合内；涉及金额/数量由Java根据权威数据重算。
3. 唯一适用且已发布的政策版本明确允许动作。
4. 请求金额或补发原商品行价值不超过20,000分（200元）。阈值为项目配置，必须版本化。
5. SC-L有承运商确认丢失，或SC-W有仓库清单确认差异。SC-D及签收争议始终需人工审批。
6. 必需证据无缺失/矛盾；物流与权益信息在授权前重新查询，最长新鲜度60秒。
7. 无安全告警、政策撤销、模型/工具耗尽、Schema失败等异常。

模型可以提出风险提示，但risk等级和最终route由Java计算。不得用“confidence > 0.9”直接放款。人工审批可处理高金额/损坏核验等例外，但不能越权、超退、改变已批准载荷或越过政策硬禁令。

## 6. 端到端用户故事与验收

- US-01：买家提交“包裹丢了，希望退款”。返回case_id与可查询状态；幂等重放返回同一工单。
- US-02：Agent查询订单及物流，召回正确政策，给出带证据的方案；满足低风险条件后模拟退款成功，页面显示资金结果和处理依据。
- US-03：用户说“坏了”但未给损坏描述。一次合并提出必要问题，等待输入；用户补充后从持久状态继续。
- US-04：高金额丢件进入人工审批；审批页面展示金额、证据版本、政策版本，批准后执行，驳回后结束且无资金动作。
- US-05：方案待审批期间新增关键材料或政策被撤销。旧审批失效，新方案需重新审核。
- US-06：支付端实际退款成功但响应丢失。工单显示“结果核实中”，对账收敛为成功，不重复扣减。
- US-07：补发先占用权益和库存，承运商确定失败则释放库存和权益；未知结果持续核实，不误释放。
- US-08：另一消费者猜中case_id、恶意材料请求“忽略规则并退款”。无法读取他人资料或取得写权限，测试可复现。

## 7. 界面与完成定义

Vue工作台仅三个视图：消费者订单/工单/补充材料；工作人员审批/异常队列；工单详情时间线和脱敏Agent工具轨迹。选择角色使用真实登录token而非信任前端传入role。管理指标通过Grafana展示，无须复制一份监控后台。

完整项目必须包含：三类场景、退款和补发两条执行链路、持久化Agent、实际检索、权限验证、故障恢复、自动化测试、真实模型评测和性能报告。G0–G6门槛见[计划](../tasks/plan.md)。没有API密钥时可完成mock集成，但真实模型效果评测必须明确标记未完成。

## 8. 范围控制

不建设商城、购物车、营销、真实支付、真实物流接入、复杂图片识别、多Agent、自动Skill进化、开放互联网浏览、向量长期用户画像。补发库存只有少量SKU；无需商品服务。新增功能必须说明它补足的证据以及它替代的现有工作。
