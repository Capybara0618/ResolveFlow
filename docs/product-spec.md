# 产品与业务规格 · v1.2核心版

范围权威见[核心范围](core-scope.md)。政策全部标记SYNTHETIC_DEMO_POLICY，不是法律或真实商家承诺。

## 1. 目标与角色

面向Agent开发、AI应用开发、Java后端实习面试的个人项目。通过可运行闭环、失败案例和真实实验展示能力，不追求公司级功能完备。

保留CUSTOMER、REVIEWER以及仅供本地运维的OPERATOR；政策通过受控种子/导入脚本管理，不开发政策运营后台。2个合成商家和至少各2个用户用于隔离测试，不做租户计费或入驻。

## 2. 业务边界

一个case对应一个订单行全部数量，仅请求REFUND；整数分、CNY、使用下单行实付快照。每个订单行最多一次成功退款，同一订单总已退+预留不能超过支付金额。

物流异常：承运商模拟权威记录明确丢失且满足政策时可建议退款；只有“物流很久没更新”的用户描述不能视为丢失。证据缺失可追问或转人工。签收争议必须人工。

商品损坏：文本材料+人工核验，始终人工审核；不做OCR/图片真假识别。错漏发、补发、部分退款等请求返回明确范围外/转人工，不生成可执行命令。

方案动作限REFUND、REQUEST_INFO、MANUAL_REVIEW、REJECT；模型提出建议，Java决定AUTO/REVIEW/NEED_INFO/BLOCK。人工不能跳过订单归属、金额上限和重复退款约束。

## 3. 自动执行条件

必须同时满足：用户已请求退款；订单已支付且在范围内；适用政策明确允许；所需证据来自已验证权威来源且版本有效；金额<=20000分；无重复/活跃退款；不是损坏或签收争议；当前revision及政策有效。

证据不足、冲突或缺政策转人工/补证，不凭模型confidence批准。Java重算金额，与建议不一致不能静默修改后执行。

## 4. 用户故事

- US-C1：本人查看订单、建单并查询处理进度。
- US-C2：Agent动态调查物流和政策，根据证据继续工具调用、追问或提出方案。
- US-C3：用户回答问题，input_revision递增并启动新run，旧结果不会覆盖。
- US-C4：审核员检查材料、核验损坏证据并批准当前有效方案。
- US-C5：退款执行超时显示“结果待确认”，对账后收敛，不重新退款。
- US-C6：开发者查看脱敏显式轨迹、模拟worker崩溃恢复、严格回放选定案例。

一个case最多2轮追问；等待用户默认72小时后转人工。只有授权消费前允许撤销/换材料；批准与消费并发用事务排序。消费后拒绝撤销或修改输入，不开发执行中取消协议。

## 5. 验收边界

自动退款、损坏审核、UNKNOWN对账、越权拒绝及动态Agent恢复能够演示。所保留链路的失败处理必须完整；不开发完整客服平台、完整权限产品或商业支付接入。
