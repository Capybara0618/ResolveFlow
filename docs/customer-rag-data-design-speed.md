# 客服RAG：知识语料、架构与速度统一验收

2026-10-21用户授权。当前进度仅tasks/todo.md顶部；本文件固定本批设计，不维护第二份进度。

## 范围与来源

先整理现有商家六条不可变规则，再加入项目已经实现的咨询流程知识，形成来源明确的离线候选知识库。只解释既有能力，不新增商家退款资格或编造时效、退货运费、七天无理由等承诺。该离线知识库不发布进业务数据库，不替换旧manifest。三家现有规则正文相同，共用知识模板只计一次，不以租户复制数夸大语料规模。

来源分三类：本仓库受控政策/产品实现文档是项目行为依据；冻结京东/小米有品/宜家原文是长文档检索参考，继续旧回归；Haystack、Sentence Transformers及已固定RAGFlow/Dify/Haystack源码是工程参考。外部品牌条款不直接当本项目政策，公开网页核查也不替换旧快照。

## 数据结构

knowledge.json为可读中文标题/正文、类型、来源文件/hash、关联规则、适用商家/版本与正文hash。六条规则逐字导入；流程资料由Codex依据仓库文档整理，明确SYNTHETIC_PROJECT_KNOWLEDGE，不称外部品牌政策或用户数据。按完整规则/短章节检索，不为小语料强切碎；每条都检查真实encoder窗口和CE pair窗口，不截断。

queries.json使用60条人工合成检索问题，30个语义家族，每家族两种表述；同一家族只进一个split，40开发/20冻结验收。都是同一实施者构造的开发验收数据，不称独立人审或盲测。单Query原文直接检索，隔离Agent生成Query的影响；后续会话Query生成需要另测，不把本批检索分数当端到端客服正确率。每题指定必要证据集合及ANSWERABLE、NEEDS_LIVE_TOOL或NOT_IN_KNOWLEDGE；后二类不纳入充分依据分母，记录检索输出但不推断已正确拒答。

## 先冻结后比较

开发集固定比较正文BM25、正文dense、三路RRF、完整候选并集GPU CE、本店全部知识GPU CE、全部知识直接读取。各路5、RRF60、最终3/5，CE原固定BGE-reranker-base、FP32/batch8/不截断，embedding原BGE-small中文、CPU4线程；复用现有CUDA解释器作为本地stdio worker，主依赖锁不变。全量读取不调用embedding/CE，只读取同一限定知识并组装来源；不可把它的覆盖满分当生成答案一定正确。

无分数阈值/多query/在线重写/新模型网格。先保存开发结果，再按“开发可回答Top3完整依据更多优先、同分RRF优于CE以减少模型依赖”的规则选候选，然后只执行一次冻结验收，不看验收后调参。全量读取作为可行性基线单列，不按其必然满覆盖把检索选型变成形式游戏。若最简单路线足够或CE退化，明确报告，不为技术栈堆组件。

## 效率口径

- 冷态：import/模型第一次加载、首条检索、索引向量构建分开。索引构建是离线成本，不混进每次检索。
- 热态：从请求已有Query到来源包组装，包含Query编码、扫描/词法、融合/精排、组装分词及其队列等待；保存真实逐次阶段与total_ms，不相加旧批局部中位数。
- 每策略每题独立执行；质量不复用分数替代推理。完整开发/验收的时延是小样本观测，另为RRF做1/4并发各40请求，线程池同一进程共享embedding锁，记录吞吐、请求延迟P50/P95、调度后总耗时，明确不是线上HTTP/DB/LLM回答性能。
- 本批源数据为文件内存索引，不伪装真实PG工具速度；当前实际PG工具另用保留generation做9题只读阶段复测，以原公共表前后hash作见证。若未执行则必须写未运行。
- body token、含来源短编号的实际packet token分别报告。速度目标暂定本机热RRF P95≤300ms、GPU CE P95≤500ms（含本地stdio、无LLM/HTTP），是验收参考而非先验成果；冷态如数秒应使用应用生命周期加载/预热，不靠掩盖首请求。

## 交付

来源/数据清单、固定输入manifest、效果与逐例退化、冷/热/并发实测、架构采用决定。实现遵循先边界测试、准备小步提交、正式测量/报告小步提交。未证明业务收益时不把实验直接上线，不自动执行付费生成模型或重建商家政策。
