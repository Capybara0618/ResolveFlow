# 模型用量记录与运行约束

2026-10-05用户要求取消项目 API / token 花销上限。本说明覆盖旧文档的消费额度规定；冻结数据和历史报告保留当时配置，不再用它们控制新评测的累计消费。

取消评测累计96次调用、0.50美元预留上限，以及评测捕获层为估算费用添加的11000字节/1024输出拦截。新运行默认不限制累计输入/输出token。调用、实际usage、失败和未知响应继续记录；没有模型余额不足的项目侧推断。

`eval.ps1 -Mode live -Case A01A,A01B`只需明确选择案例。用量文件默认继续使用`tmp/evaluation-live-budget.json`，避免丢失原96次记录；可用`-LiveUsage`指定路径，`-LiveBudget`仍兼容。读取旧文件时将原limit保留为historical_limit，新limit为null；历史reserved_usd只保留，不再计算或作为账单。调用前保存累计次数，包括失败/未知网络结果；进程锁防止用量丢失。

单工单的迭代次数（生产12、评测6）、工具/本地读取次数、无进展检测、超时与deadline继续约束运行；每次请求的输入窗口8192、输出长度1024也保留。它们负责终止和控制请求大小。Java金额、权限、引用与fence不变。

取消消费上限不自动执行收费评测或消费业务队列。本次不调用真实模型、不重启服务。以后运行真实模型仍按用户明确任务选择案例。
