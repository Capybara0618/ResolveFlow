# 客服 Agent 双端预期图 v1

2026-10-20。[打开可交互原型](index.html)，也可直接用浏览器打开本目录的 `index.html`。这是下一阶段功能的设计稿；对话、人工交接、申请和回复均在浏览器内演示，不访问业务 API，刷新后不保存。本轮没有实现新的客服后台。

依据：[首场景规格](../customer-agent-scenario-v1.md)、[双端与多租户决定](../customer-agent-multitenant-v0.md)、[12 个开发样例](../../evals/customer-agent-v1/dev-dialogues.json)。界面沿用现有商城商品卡片、白底蓝色和桌面字号。

## 用户端

| 视图 | 预期体验与操作 | 截图 |
| --- | --- | --- |
| [选择商品](index.html#orders) | 打开售后聊天后看本人跨店订单，选择具体商品；左侧保留各商品的咨询历史 | [orders](images/orders.png) |
| [咨询](index.html#chat) | 自然表达问题，右侧展示当前商品、物流和适用政策；可以纠正、插问、换商品 | [chat](images/chat.png) |
| [转交预览](index.html#handoff) | 查看/修改问题摘要、事实和待核查事项，选择共享相关原文；确认后才提交咨询核查单 | [handoff](images/handoff.png) |
| [退款确认](index.html#refund) | 展示整行实付、诉求和材料，客户确认才提交退款申请；提交后显示待核验 | [refund](images/refund.png) |
| [人工接续](index.html#progress) | 在原会话看商家回复、补充材料和进度；输入默认补充给商家，也可显式切到询问智能助手 | [progress](images/progress.png) |

顶部视图切换栏仅用于看设计稿，不作为正式产品的导航。商品卡片与历史入口可切换上下文，消息接收方始终可见。原型不模拟自由输入后的真实模型推理，发送只用于展示消息与接收方。

人工咨询无需退款；客户确认转交后，商家才获得预览中选择共享的摘要/原文。咨询后再申请退款需另行确认，并关联原核查记录。退款工单的审批、执行中和执行成功沿用现有流程，不能把“提交申请”显示成“已退款”。

## 商家端

| 视图 | 预期体验与操作 | 截图 |
| --- | --- | --- |
| [待办](index.html#queue) | 在现有工作台分辨咨询核查与退款申请；先看到客户诉求、状态与待办 | [queue](images/queue.png) |
| [核查详情](index.html#detail) | 看客户共享内容、系统事实、适用政策与 Agent 建议，核查后回复/要求补充；建议与人工结论有明确作者 | [detail](images/detail.png) |

第一版商家通过工作台操作，没有独立的 Agent 聊天窗口。原型商家视图固定展示松间数码的签收核查样例；用户端可切到拾光家居验证上下文，尚未绘制 B 店独立工作台页面。

商家回复到客户原会话；“已回复”与“已解决”分开，示例由客户确认解决后结束。咨询状态名称是产品草案，后续协议冻结时再确定字段和枚举，不直接修改现有退款 Case 契约。

## 数据与状态约定

- [samples.js](samples.js) 的店铺、商品、金额、物流状态和订单尾号来自本轮 [7 笔真实模拟订单](../../reports/customer-agent-design-v1/runtime-samples.json)，不是商用交易。
- 签收争议中的“未收到”、商家回复、政策解释文案和调查报告为设计示例；不代表发生过真实调查或模型生成。政策依据对应场景规格列出的现有商家规则，正式检索仍需后端按订单绑定店铺/版本。
- 切换商品恢复各自的原型消息和操作状态；A 店内容不随用户切换提交给 B 店。正式实现还需后端身份、归属及异步回复版本检查，页面演示不能证明接口隔离已完成。
- “仅咨询 → 转交预览 → 等待/补充/回复 → 已解决”与“准备退款 → 客户确认 → 待核验”分别演示。预览关闭不创建记录；客户纠正后旧摘要的失效、已有退款单接续与并发输入还需后端实现。

## 验证与复现

使用已安装的 Edge 和 Playwright，在 1280/1440/1680 像素三种桌面宽度检查全部 7 个视图，无横向溢出；截图以 1440 像素宽生成。另检查 14 项原型交互：转交、接收方、政策抽屉、换店/独立消息、取消、退款待核验、咨询/退款区分、摘要修改、共享原文、商家回复、补充、解决及在途上下文。

[验证结果](../../reports/customer-agent-design-v1/preview-check.json)记录原型检查，不是 Agent 效果、真实人工接续或接口端到端验收。尚未验收移动端、键盘无障碍与真实模型问答。

可在仓库根目录使用已配置的 Node/Playwright 重跑，无需启动业务服务或模型：

```powershell
# 若 Playwright 不在当前 Node 的解析路径，先将既有依赖目录加入 NODE_PATH。
node scripts/check_customer_agent_preview.cjs
```

脚本使用本地文件与已安装的 Edge，重写上述截图和检查报告，不安装浏览器；其他已安装 Chromium 通道可通过 `CUSTOMER_PREVIEW_BROWSER` 指定。

## 接下来如何实现

先把本图、场景与开发样例对应成会话/消息/咨询核查单/退款 Case 的数据关系及 API，确定共享快照、状态转换、幂等提交和旧回复处理；然后先贯通“选商品 → 咨询 → 人工核查 → 商家回复 → 客户补充”一条链路，再接退款确认与多种物流分支。

AgentScope 继续负责唯一主循环，Harness 保持权限、预算和恢复约束；本轮不更换框架或重建支付/退款基础。
