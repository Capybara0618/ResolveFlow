## 产品结构

只有客户端与商家端两套导航。商家端的售后专员沿用 REVIEWER 角色；管理员沿用 MERCHANT_ADMIN，增加管理菜单。管理员只管理本商家，不是平台超级管理员。账号绑定单一商家，不提供跨商家切换。

客户端导航：我的订单、我的申请。待回答问题在申请列表提醒并定位详情，不另建与业务重复的消息系统。

商家专员导航：公共队列、我的工单、需关注、历史查询。管理员额外有工单概览、人员管理、政策资料；相同工单详情及操作组件复用。

## 完整体验流程

### 客户
登录(01) → 我的订单(02) → 申请退款(03) → 我的申请(04) → 申请详情(05)。
- 不需补证：等待调查与人工审核 → 结果(06)。
- 需要补证：详情直接回答 → 新调查 → 人工审核 → 结果。
- 允许撤销：详情填写撤销理由并确认 → 已撤销结果。授权消费后不出现可执行撤销入口。
- 申请仍可追加材料时：详情中的“补充材料”文本区，保存后刷新材料与调查状态；不是媒体上传。
- 错误或登录失效：按13反馈，不显示保存成功或退款成功。

### 售后专员
登录(01) → 未领取队列(07) → 领取 → 工单详情(08)。
1. 阅读原始申请和材料；按需打开调查依据(15)与对应政策原文。
2. 判断事实、主张、证据冲突和缺口；需要核验则打开09，核验保存后等待新建议，旧建议失效。
3. 需要客户回答：09发送问题 → 待补证 → 客户05回答 → 新调查 → 回到08；保留当前负责人。
4. 形成有效方案后：09确认批准或拒绝。批准仅触发后端模拟执行；详情显示处理中、待确认或最终结果。
5. Agent不可用：15人工方案 → 服务端复核 → 人工审批。失败不冒充成功，不让客户看到原始模型请求。
6. 我的工单/需关注/历史在14；可释放或转交的工单需记录理由。终态仅查看。

### 商家管理员
登录(01) → 本商家概览(10) → 查看未领取/异常 → 分配、转交或明确接管 → 共用详情(08)。
人员管理(11)支持新增账号、显示名称、角色、启停和密码重置；初始或重置密码只输入，绝不回读。相关变更使旧会话失效。
政策(12)只读，版本与索引状态真实展示。执行结果UNKNOWN只能查看与等待现有对账，不换操作ID重付。

## 操作与状态合同

| 场景 | 必须呈现的行为 |
| --- | --- |
| 新申请 | 固定全额、本人订单、幂等创建；有活跃申请时跳转已有申请 |
| 补证 | 自动关联当前问题；最多两轮、72小时且受工单期限约束；回答后新修订调查 |
| 待补证撤销 | 未消费且服务器允许时可撤销；不能因通用示例灰色按钮一律禁止 |
| 核验/新材料 | 当前建议标旧版失效，审批禁用直到有当前有效方案；负责人不丢失 |
| 他人负责 | 姓名明确，工单只读；管理员先接管再做人工操作 |
| 版本冲突 | 刷新当前资料、解释冲突、保留表单草稿；不自动重提交批准 |
| 审批 | 当前负责人、当前材料/授权版本、有效政策依据同时通过；置信度不当权限 |
| 授权消费后 | 禁止修改材料、核验、取消和新批准/拒绝；执行系统继续推进 |
| UNKNOWN | 结果待确认；保留占用，不能显示失败后引导再退款 |
| 终态 | 成功/拒绝/撤销有相应公开理由或结果，最后负责人留痕；只读 |
| 网络/登录错误 | 读取失败可重试；不可把未确认业务写入显示成功；恢复登录重新核验范围 |

## 视觉与数据实施标准

- 白蓝桌面风格：主色 #0b5cff，背景 #f6f8fc，深蓝标题，浅边框，约10px圆角；正式桌面以1440/1680宽度核对，1280不遮挡主操作。
- 共用60px页头，约180px侧栏；审核详情参考最初四列构图，原文与AI解释分开，长内容分区滚动，主要操作可发现。
- 页面文字使用客户/售后专员/商家管理员；底层枚举不为改名重建。后端允许动作与真实字段决定按钮及内容。
- 图中名称、编号、数量、商品示意图都是合成例子。当前无商品图片字段时用明确占位；没有展示编号字段则显示真实编号或另行同步契约，不能仅在前端编造。
- 不新增虚构收货人、会员、优惠券、支付流水、审批额度、媒体真实性；客户不展示工作人员身份、完整调查工具记录、原始模型请求。
- 列表搜索、计数和提醒属于目标需求；只有服务器支持才能展示可用控件。计数来自真实查询，不把设计样例数字写入产品。
- 所有政策例文均为图示，最终来自工单钉住的真实政策原文与版本，不能把绘图内容写进政策库。
- 页面的微文案、图标、自动生成字符不作为字段契约。与本文规则有差异的地方按规则实现，并在视觉检查中明确记录。
