# 客服 Agent：进入效果评测前的实施与验收

2026-10-21。用户授权做到可以开始评测，暂不更新简历、不执行正式效果评测。本文件规定本批实现与评测口径；实际进度只维护在 [todo 顶部](../tasks/todo.md)。沿用 [业务范围](core-scope.md)、[客服工作台](customer-support-workspace.md)、[现有优化](customer-agent-optimization-v1.md)和 [RAG 架构](customer-rag-architecture-v1.md)。

## 1. 目标架构

Java 冻结当前输入、订单行归属、消息对象、政策版本和最近会话原文 → 分层上下文 → AgentScope 唯一循环中的一次模型调用同时输出任务状态和下一动作 → 受限业务读取 / 历史读回 / 政策 RAG / 使用指南 → 记录来源与失败 → 下一次模型决策 → 结构与引用检查 → Java 按版本发布回答。客户确认共享后商家处理，原退款申请与授权职责不变。

- 意图与任务：同次决策中的结构化标注，不增加分类模型，不按关键词固定工具路径。区分物流、资格、办理、人工核查、商品问题和其他；混合诉求拆成最多 8 项。每项保留原诉求、状态及已读依据，状态是模型判断而非业务授权。
- 每轮重新核对客户新消息与历史；前轮任务仅作为模型记忆提示，不继承实时订单事实或旧 run 的 O/P 引用。纠正、取消或转移诉求须明确更新，不能把客户声称退款成功写成系统事实。
- 上下文：当前请求、可信会话状态、商品及政策绑定、任务状态和已读业务/政策依据优先保留；最近原文尽量完整，更早原文降为带长度、截断标记和读回位置的索引。依据按原引用去重，完整政策的条件/例外不按句子机械裁剪。
- 预算：用实际 provider 请求计数器检查，依次压缩历史而非扩大窗口；无法装入的必需上下文明确失败。增加本 run 不可变原文的局部读回，偏移按 Unicode 字符计数，避免长消息只能看到前 160 字。每次读回同样受原本地预算/持久调用账控制。
- RAG：Agent 在同次决策生成独立 Query，补全指代、沿用已纠正信息并保留否定/假设；按所缺依据重新聚焦。不加无证据的强制状态，不增加额外改写 LLM。保留三路召回、RRF、商家/版本/generation 过滤及完整规则。CrossEncoder 保留为已有实验候选，不因技术名词增加默认路径。
- 输出：有任务状态时，回答前不能遗留未处理任务；可明确缺信息、暂不可查或需商家。引用必须来自当前 run，任务关联的依据须真正读取；结构检查不能证明任意答案语义正确，完整性仍由后续业务评分审查。

## 2. 实施拆分

1. 文档与验收口径；保持原数据、旧报告、简历及四个历史脏文件。
2. 任务协议、同次决策接线与精确反馈；失败/混合/遗漏等不同表述先做脚本工程测试。
3. 分层上下文、精确请求预算与局部原文读回；长历史、尾部纠正、事实冲突、政策例外、超限和恢复分别验证。
4. Java 冻结前轮模型任务提示、Python 重新核对和去掉旧引用；原会话/fence/私有共享语义不变。若无需新增公共字段，不修改对外聊天协议。
5. 准备新评测输入、评分结构、无模型预检与运行说明；只做工程/隔离集成验证，停在正式效果评测之前。

## 3. 后续评测协议

本批不执行下列效果测量，不填写目标分数，也不按合成输入强行保证提升。

Agent 主指标为逐会话任务完成率：所有必答子问题正确且可操作；必要来源、关键条件与纠正均满足，无虚构业务动作。完整 / 部分 / 失败分别记录，超时/工具失败/格式停止也进入分母。只在子集正确不能计完整。对照采用同模型、政策、工具、输入和预算的固定调查流程，另保留改前生产版本回归；两个对照用途不同，不混称因果消融。

场景覆盖单物流、签收争议、资格与办理混合、商品问题和材料责任、个人原因的政策边界、独立人工咨询、消息对象切换、已解决后补充、长历史尾部纠正、用户撤回退款意图、工具故障、政策条件/例外、缺依据不能推断。开发用例与新验收变体分开，合成/开发可见身份明确，不称真实用户或独立人审。

RAG 主指标为固定问题的 Top-5 必要依据完整覆盖率：金标是实际绑定政策原文与所需条件；无答案题单列，不放进可答覆盖率分母。比较 dense / BM25 / 三路 RRF，必要时另比较 Agent 原 Query 与上下文补全 Query。排名指标、最终回答质量、无答案处理分别报告。保留既有漏召回，不能改旧 Gold 或只挑命中题。

效率辅助项：实际模型请求和 provider token、完整接口耗时、检索 P50/P95、启动预热和首次查询分开。上下文压缩比较实际发送输入，先核对事实/纠正保留，再解释 token；脚本 mock token 不替代真实费用。小样本 P95 只描述本批。

## 4. 进入评测的工程门槛

- 唯一 AgentScope 循环；任务理解与动作共用一次模型请求，无隐藏重试或额外摘要模型。
- 真实发送请求中可检查任务、最近原文、截断位置、来源/版本/冲突、失败状态和反馈。
- 原文读回可定位尾部纠正；政策条件不被压缩改写，超限不会静默删除当前输入。
- 缓存响应恢复能重建任务与上下文，无新模型/外部业务读，manifest 包含新代码与配置。
- Java 隔离 HTTP 验证跨轮任务冻结、过期回答/主体边界及原人工共享链路；Python 契约/SDK/PG 验证通过。公共协议未变则不强行改 UI。
- 评测输入和评分可预检，工具/政策 pins 可复核；正式模型结果仍待后续运行。
- 正式业务服务与原队列保持关闭；只启动需要的测试依赖并保留数据，完成后恢复原状态。

达到以上门槛表示可开始评测，不表示已经证实任务完成率提升或已重新完成全栈演示。
