# 当前客服版本集中评测 v1

2026-10-24，用户批准在已采用的 orchestrated-v1 上继续评测。本批冻结业务实现，先记录绝对效果、失败分布及延迟，不更新简历或重做架构。

## Agent

复用 `evals/customer-agent-eval-v2/scenarios.json` 的14组44轮，原问题、顺序、事实快照和逐轮判据保持。包含物流/签收、商品问题、个人原因、混合诉求、独立人工、人工后的私有咨询、纠正撤回、长历史、来源故障、政策条件及暂停恢复。它们是已用于开发的合成回归样本，不是独立盲测。

唯一生产循环、提示、预算、来源校验和持久化均使用当前实现，显式 orchestrated-v1；DeepSeek Flash，thinking disabled、temperature 0、JSON、流式，容量32768。每轮沿原12模型调用/120秒期限，不增加重试。每条输入仅执行一次，失败仍进入44轮分母，继续后续预定输入。没有预设完整工具路径或标准答案注入。

订单/物流/历史采用冻结的、按run绑定的合成HTTP适配器；政策来自现存只读PG精确generation；run/call仅落本批独占临时schema。跨轮传递实际已发布回答，以及成功或失败结果中实际被接受的conversation_update；失败不能伪造助手回答。此范围不是完整Java/网页端到端复测，不创建Case、审批或退款。

预先冻结源码、脚本、数据及本地embedding权重hash。运行中不改业务源码、Gold或失败答案；完整保存实际请求正文、返回决策、usage、工具结果、进度事件、各轮结果和journal。凭据不入报告。未知/异常请求也记账，不能只统计成功。

主指标为源审通过轮数/44、全部轮次通过的会话数/14；另列正式发布率、各场景失败及结构化原因。逐轮依据既有criteria，结合原用户输入、实际来源、陈述是否纠正/撤回、事项生命周期、独立摘要和权限判断，不以SUCCEEDED或关键词命中替代语义正确。审阅者为本次Codex，非独立人工盲审。

延迟分别统计整轮run耗时、首个临时正文、最终保留attempt的首段正文、模型请求及RAG工具耗时的p50/p95和样本数；无正文及失败另列，不从成功分母中消失。进度接收使用原ProgressReporter配本地HTTP transport；这是服务端投影接收耗时，不含Java/SSE代理、网络和浏览器DOM。此前真实网页单例保持独立证据。记录调用数及真实token，不把阶段数当ReAct轮数。

## RAG

1. 外部原始政策：复用29问题、66片段及原子证据标签，按当前三路字段召回/RRF函数比较dense、正文BM25、标题BM25及融合的Top3/Top5完整证据覆盖。17个ANSWERABLE作为主要分母，PARTIAL单列；使用已缓存同输入向量，0新模型/embedding请求。原文、标注及缓存hash固定，结果不是当前商城完整政策输入模式的同义指标，也不是独立holdout。
2. 商城运行路径：复用9条查询，先独立预热，再10轮共90次调用当前BoundSources.search，实际只读PG。首调用、模型加载/预热与热态分开。记录COMPLETE_SMALL_SET/RANKED、返回条数、必要规则输入覆盖和p50/p95；六条规则整包输入的覆盖是结构性结果，不能宣称排序胜过BM25。此项不包含LLM生成或浏览器响应。

不在本批临时增加CrossEncoder、改写器或GPU实验。GPU是否改善已采用路径，留给结果证明瓶颈后讨论。

## 顺序和交付

先冻结口径及评测驱动的针对性测试，0付费预检；再只读RAG、一次44轮真实生成，最后逐轮源审和统一报告。每个验证后的独立步骤精确commit并普通push。公开业务表/政策索引前后hash核验，临时schema导出成功后才删除本批自己的schema。历史四处脏文件和旧报告保持。

结果若不理想，仍交付原始分母和根因。旧版成绩只能作历史参考，本批不据其计算提升率；后续如需提升率，再冻结同模型/同输入/同条件的固定流程对照。
