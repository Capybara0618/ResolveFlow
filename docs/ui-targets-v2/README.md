## 角色与页面范围

产品仍是个人项目范围的桌面售后网页：多个客户提交退款申请，一个商家的多个工作人员先后处理，Agent/RAG辅助、人最终决定。只有客户端和共用商家端；售后专员是REVIEWER，商家管理员是MERCHANT_ADMIN，只管理本商家，须明确接管才成为当前负责人。账号绑定单一商家，不提供跨租户切换、平台超级管理员、商城、移动端、媒体上传或真实支付。

| 使用者 | 固定导航 | 数据及操作边界 |
| --- | --- | --- |
| 客户 | 我的订单、我的申请 | 本商家内本人订单与申请；只看公开进度、问题、自己的材料/回答与结果 |
| 售后专员 | 公共队列、我的工单、需关注、历史查询 | 本商家；人工写入还须当前负责人、有效版本及允许动作 |
| 商家管理员 | 专员四项＋工单概览、人员管理、政策资料 | 本商家管理；无隐式审批权限，不绕过已消费冻结 |

页头商家名称是静态身份信息。姓名/角色菜单仅包含账号身份和退出登录；没有装饰性通知铃。待回答问题、待办与异常通过真实列表/概览和工单更新发现，不新增独立消息中心。图13、16–19是独立状态/弹窗展示板，不是额外的产品路由；客户实际页面不会展示工作人员身份或内部方案。

## 完整体验与状态连接

客户：01→02→03→04/05。商家：01→07领取→08阅读与调查→09核验/补证/决定。管理员：01→10协调或接管→共用08；管理账号走11/16，查阅政策走12。

```text
申请及初始材料保存 → 排队/调查 → 当前方案 → 人工审核
                                  ↑               ├─拒绝 → 双方只读结果
                                  │               └─批准 → 模拟执行 → 结果
                       核验或新材料保存
                                  ↑
                       客户回答问题（05/17）
                                  ↑
                       要求补证（09/18）
```

这是一条可重复调查的流程，不能用一次性线性进度条暗示必须经历所有阶段或只能问答一次。需要补证期间保留负责人；回答与核验进入新材料修订/新调查，历史记录保留，旧建议标注失效。第二轮回答后仍可调查，只是不允许第三轮追问。

## 按钮、数据及错误的实施合同

以下是图册的精确规则；服务端必须执行，前端不能仅靠隐藏按钮保护权限。若当前API缺字段，先同步契约与生产/消费者，不编造一个前端判断来冒充服务器允许。

| 条件/操作 | 必须实现的行为 |
| --- | --- |
| 创建申请 | 本人订单、单订单行全量CNY模拟退款；金额固定取原行实付；重复提交复用原幂等结果 |
| 创建结果未确认 | 先查原幂等结果/活跃申请，不直接重新创建；确认申请已存在才重试未保存材料 |
| 创建成功、材料保存失败 | 明确两个结果；进入已建申请，保留未保存文本，仅重试该材料，不再次创建工单 |
| 问题回答 | question_id由当前问题关联，不让客户手填；等待状态只回答当前有效问题；必填、最多两轮、72小时且受工单截止限制 |
| 追加文本材料 | 仅服务器允许时显示可执行表单；等待问题回答不能绕开问题流程；无图片/视频上传；追加仍是客户陈述 |
| 核验表单 | 无默认“已通过”；结果和依据必填；保存后旧建议失效，等当前调查结果，不自动批准 |
| 负责人 | 同时最多一人；领取、释放、转交、接管只改协作信息，不增加input_revision或启动模型；冲突后刷新，原负责人失去写权限 |
| 他人负责 | 专员只读；管理员可填理由显式接管，成功后才操作；停用负责人进入管理员待办 |
| 来源阅读 | 以保存结果绑定的bundle/version/rule/chunk/hash展示原文和定位，模型解释独立分区；无正文就说明未保存/不可用，不找另一版替代 |
| 建议标识 | 当前材料修订、建议所属修订、有效/失效与调查状态分开显示；实际模型模式mock/live/unknown与数据来源合成/真实分开；未知不猜测 |
| 当前可审批 | 当前负责人、有效当前方案、材料/授权/协作版本、绑定政策及服务端复核均有效；人工最后确认；confidence不授予权限 |
| Agent失败 | 不显示假建议；允许的当前负责人可填写人工方案；保存→服务端复核→人工决定，复核失败保留草稿和原因 |
| 等待客户 | 保留问题/回答历史及负责人；不可连续重复发问；过期回答禁用并展示等待工作人员处理，不自动退款或判为退款失败 |
| 授权消费前 | 撤销/修改仍以当前服务器允许动作和版本为准；AUTHORIZED也不能硬编码永远可撤销；撤销成功让旧授权revision失效 |
| 授权消费后 | 输入冻结；材料、核验、人工方案、取消、新批准/拒绝均禁止，不能只用EXECUTING枚举判断 |
| UNKNOWN | 显示结果待确认；保留占用、同一原操作继续对账；仅允许读取/刷新，不释放、不换ID重付 |
| 成功/拒绝/撤销/明确失败 | 展示持久结果及适当公开原因，终态只读；明确失败不画“再退款”按钮，不借此突破同行资金约束 |
| 账号维护 | 本商家，全局唯一用户名，商家归属固定；密码不回读；停用/角色更新/密码重置使旧会话失效；最后一个启用管理员不可停用或降级 |
| 空表单/提交中 | 必填缺失时按钮禁用；提交中防重复；失败保留本登录会话草稿，退出或切换账号清除，不泄露跨身份草稿 |
| 网络写入结果未知 | 不当作失败后自动重提交审批/退款；先读取原结果和版本，冲突提示重新确认；读取失败可重试 |

## 视觉、样例与位图的使用方式

保留主色#0b5cff、浅灰蓝背景、深蓝标题、轻边框和约10px圆角。共用页头/角色侧栏/卡片/按钮，商家详情保持原始资料、Agent与政策、客户订单上下文及主操作可见。正式实现以1440/1680桌面宽度集中核验，1280不遮挡操作；长正文与历史允许分区滚动，不照固定图片高度截断。

主示例固定为松间数码、客户周雨、无线降噪耳机Pro深空灰×1、¥329.00，订单OD202609280001付款2026-09-28 10:15，申请RF20261001001创建2026-10-01 14:22；图中的RF001是其缩写。05、17、18、19展示不同时间/前提的独立状态，不能把这些状态同时写进一张工单。状态板上人员/版本的摘要是设计说明，不是客户可见的内部字段。

其他列表行、人员、图中政策例文及计数均为合成视觉样例，不是一套可直接导入的共享fixture。正式实施必须使用一致的受控样例或真实数据：后端编号、主体、商品、金额、状态、创建/更新时间不得由位图抄入。商品图没有真实字段时使用明确占位图。政策例文不导入政策库，历史工单读其绑定的原版本。

已保留的少量位图差异见[复查记录](review.md)：04导航数字应改为真实待答数；10/15仍有生成的字符计数，限制取实际契约；15模式标签应明确mock/live/unknown，来源元数据应可展开；19商品名和页头简称按真实字段。生成字符不是实现规范，也不新增相应字段或功能。

设计规则按范围规格和已批准的[双端补齐方案](../product-completion-review.md)执行。本图册不建立第二份功能进度；当前暂停状态、已交付成果和未提交原型只看[todo顶部](../../tasks/todo.md)。用户决定恢复业务实施后，从现有新第二批原型接续，保留原五批顺序并按批集中验证，不为每个按钮单独要求验收。
