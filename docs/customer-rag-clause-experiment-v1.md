# 条款定位与父块去重实验v1

2026-10-25，用户授权修复开发集暴露的组合证据覆盖问题。先验证低成本的索引表示与父块去重，不调用生成API，不修改Agent或生产RAG，不运行60验收题。原v3的15份正文、100题/Gold、344父块及旧分数保留。

## 假设与范围

开发集CE27/32完整、组合5/8，而必要原文已在候选池。点式相关性不能保证复合事项覆盖是已确认限制；多个事项合并为320字块造成信号稀释是待验证假设。本轮只改变检索定位单位，并显式区分父块重复占位，不同时加入Query改写或扩大TopK。

从现有父块的原文fragment构造定位子片段：每个HTML段落/原文切片单独编码，保留相同标题/章节前缀；长表格已绑定的真实表头与正文切片仍成一组，不将孤立表头当正文候选。相同原文跨度合并子片段并保留所有父块绑定。所有选择只看原始文本/元数据，不读取问题Gold或题号。

检索仍按同一品牌及版本硬过滤，BGE、BM25、RRF常数60、每路20及融合后20候选、固定CE/GPU精度保持。最终回传原v3父块，最多3个不同父块，共用8000字符/4096token预算。父块内容不增加，也不扩大父章节；各新方法均获得相同的子片段和父块能力，避免只给最终候选额外资料。

## 预定六路

1. packed-ce：原v3混合RRF+CE，使用原父块/向量，新跑作当批速度与质量参照。
2. clause-dense：子片段纯向量，按父块去重后回传。
3. clause-bm25：子片段BM25，按父块去重后回传。
4. clause-rrf：子片段两路RRF，按父块去重后回传。
5. clause-ce-naive：子片段RRF+CE，仅前三子命中映射父块，不继续补足去重后空位。
6. clause-ce-grouped：相同子片段RRF+CE，先按最高子命中归并父块，再取前三不同父块。

主比较grouped与packed-ce，检验完整方案能否改善组合覆盖；naive与grouped隔离父块去重占位，clause-dense/BM25/RRF为相同表示与回传能力的强对照。不能把子片段/父块表示的收益全归因于RRF或CE。naive实际可能返回少于3父块，实际文本体积同时报告。

同40开发题×6路×3次=720本地请求，只运行一次冻结版本，不按结果增加参数网格。质量仅计32可答题第一轮，复杂24/普通8及四类别完整列；8语料外保留，不算拒答准确率。三轮只用于计时及稳定性，失败保留不追分。

主指标仍为必要证据完整覆盖；父块回传后的Top3属于子片段定位的上下文覆盖，不得称“前三原子条款召回”。附子候选/父候选覆盖、Top1完整、剩余问题的来源排名、父块实际数量与正文tokens。计时包括Query编码、子召回/融合/CE、父块去重/组装，排除索引构建/加载/标签；各路轮换，通用词法/编码/8CE候选预热。

## 实施与停止条件

先关键失败检查与实现、构建本地子向量、核对模型窗口，冻结新manifest并提交推送后执行。所有原来源/Gold/父块/模型/旧manifest及结果须保持hash一致。结果无论正负都记录，不在本次内继续叠加其他算法；若组合覆盖仍不足，再基于证据讨论子Query或条款层级上下文，不自动付费或进入验收。当前进度仅tasks/todo.md顶部维护，职责及实验结论随批更新architecture-evolution.md。
