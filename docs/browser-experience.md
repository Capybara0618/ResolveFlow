# 商城入口（2026-10-03）

启动仍用根目录`demo.ps1`。浏览器打开`http://127.0.0.1:5174/#/shop`可不登录浏览两店商品，登录`demo-buyer` / `demo-pass-4001`后选择规格和数量、确认服务器报价、提交待支付草稿。当前第二批止于草稿，付款在第三批接入；草稿不会被当作已支付订单或退款资格。已有两店本人订单/申请继续页头入口。仅逛商城无需`-Live`，不调用模型；下方原售后体验说明继续适用。

# 浏览器体验指南

适用范围：桌面网页、两逻辑商家、客户/售后专员/商家管理员、单订单行全额模拟退款。页面入口是正式产品，不是静态预览。实际闭环及限制见[第五批报告](../reports/product-flow.md)。

## 启动与停止

本机依赖已安装时，先启动Docker Desktop，在仓库根目录打开PowerShell：

```powershell
cd 'E:\Code\Agent+Backend'
.\demo.ps1 -Live
```

脚本准备隔离演示数据库与消息设施、构建并启动三个Java服务、启动Agent和前端，自动打开[浏览器工作台](http://127.0.0.1:5174)。Gateway是8180，Agent是8182；不要混用原先5173的另一个前端。第一次构建较慢，已启动时再次执行会复用服务。用户环境变量`Deepseek_API_KEY`用于官方DeepSeek `deepseek-flash`，密钥不需写入项目文件。缺少密钥时脚本明确报错。

```powershell
.\demo.ps1 status                  # 查看真实进程与样本状态
.\demo.ps1 stop                    # 停止，保留订单、工单、账号和运行记录
.\demo.ps1 -Live -SkipBuild         # 已构建且源码未变时快速重启
.\demo.ps1 -Live -NoBrowser         # 启动后自行打开5174
.\demo.ps1                         # 查看已有结果，不开启新Agent调查
```

只读Agent模式仍允许网页提交申请、人工处理和Java模拟退款；新调查会排队，不会自动生成模型建议。完整新申请体验用`-Live`，新增材料、核验和补证回答都可能产生收费调用。模型失败或超出预算可由负责人提出人工方案，再单独审批。默认命令不运行本次验收脚本，不重置历史run。

这是已有环境的日常入口；全新电脑仍需按[工程说明](engineering.md)和README安装Java21、Python3.12及锁定依赖、前端工具和Docker。遇到启动失败先看命令末尾日志路径与`status`，不要清库/删卷。`SkipBuild`不能用于部署修改过的Java源码。

## 推荐走一遍

1. 客户进入“我的订单”，选择显示“申请退款”的本人订单行，填写问题及文本材料。已退款的订单只能查看；已有处理中申请直接“查看申请”。
2. 专员进入“公共队列”，点击刷新或等待30秒空闲更新，找到新申请，明确领取。阅读原始材料、调查分项、模型来源及绑定政策引用，展开原文核对条件与例外。
3. 需要补充时写明具体问题并提交“请求补证”。客户进入“我的申请”，点击当前问题回答；无需填写工单或问题内部ID。回答或核验产生新修订，旧建议会失效，等当前调查结果再审批。
4. 可将工单转交另一启用专员；管理员需明确接管。旧负责人、旧弹窗或旧协作版本提交会冲突，刷新后重新核对。
5. 当前负责人填写理由，批准授权或拒绝。批准后仍需等待Java执行结果；成功时客户看到模拟退款金额与公开理由。调查失败可以先形成人工方案，保存方案不会自动批准。
6. 客户也可在授权未消费、服务器允许时撤销。已消费的工单冻结材料/审批输入；“结果待确认”只能跟踪原退款操作，不能重新支付。

客户可见且空闲的申请列表每15秒发现变化，详情可用刷新；多页列表会保留记录并提示刷新。停用账号的旧请求401并退出，跨商家/跨客户详情404。不要尝试用账号角色或URL改变服务器的数据范围。
