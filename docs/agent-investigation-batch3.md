# 第三批：调查与终止（2026-10-05）

用户批准优化本批并调用真实 DeepSeek。沿用第二批上下文、五个只读 MCP、AgentScope 唯一循环和冻结 aligned-v2；不修改政策、Gold、召回算法、资金授权或业务数据。

## 目标及边界

模型按当前证据选择能消除关键缺口的动作；读到适用政策和足够事实后给建议，存在无法自行核实的缺口则有针对性追问或交给商家。没有固定的全工具路线，也不要求每案把五个工具读完。系统能读取的信息不能转嫁给客户；客户原话、人工核验及政策条件仍保留来源，不将读取成功解释为证据成立。

真实基线首先选开发集 A01A/B（未发货配对）、A05A/B（丢失配对）。基线四例共八次调用均因错误输出包装停止，且出现索要已绑定订单号的无效追问。先明确扁平动作示例及调查/结束原则，再按真实轨迹决定必要的 Harness 修正。不能宽松解析错误包装、伪造引用或通过改答案使评测通过。

## 实施和验证

1. 动作协议提供可模仿的扁平 JSON 示例，明确占位引用只表示格式；保持严格 ABI、一次修复、所有调用预占与记录。
2. 精简调查原则：优先系统读取，问答不重复；提出退款需要对应政策条件的实际证据；缺证区分客户可提供信息和商家核验。具备依据及时停止，不用剩余预算填充无关读取。
3. 用失败测试固定边界；继续覆盖无进展两次反馈/第三次执行前停止、不同页/新来源版本继续、预算/取消、短引用、恢复/fence与离线回放。生产变更创建新的回放版本，旧包不覆盖。
4. 开发集做同例真实对照，收敛阶段跑测试集签收争议及质量问题配对 A09A/B、A13A/B。这些测试资产已经参与工程验证，不能称完全盲测；真实结果不等于上线准确率。实际 A13B 的第5轮被累计调用上限阻止，不能算通过；随后只做本地格式/容量收口，没有重置预算再收费。
5. 集中报告记录实际动作、关键取证、终止原因、错误包装、无效追问、依据/例外解释、实际 usage 与费用预留。语义检查标明由本次执行者复核，独立专家审查仍待完成。

## 已落实的证据边界

现有命名条款 `R-LOST-001`、`R-DMG-001` 增加可检验的来源门槛：引用当前已付可退订单、当前 revision 的材料外层 Observation；人工 CONFIRMED 必须关联本案客户陈述，且核验与目标的四字段身份均在材料工具结果中。最新未知/反驳/同版矛盾核验不能被旧确认遮盖。丢失另需承运 LOST，无签收事件；质量可用订单明确送达，不强制再读物流，已读的相反物流不能隐瞒。仅资金限制/在途/签收争议的条款不独立建立退款资格。未知条款仍走原引用检查，不新增通用政策规则引擎。

这只检查来源和必要事实，不证明人工结论内容一定正确，也不自动判定所有自然语言例外。最终审批、付款占用及退款不变量仍由 Java 执行。新 verifier v4 在 SDK 动作入口和最终回调入口共同使用，恢复/回放继续复用同一校验；旧 run 不换 manifest。
