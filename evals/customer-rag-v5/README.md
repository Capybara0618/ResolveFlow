# 客服知识库与检索验收 v1

2026-10-21。配套[设计与速度协议](../../docs/customer-rag-data-design-speed.md)。知识库是离线候选，未发布/导入业务库；原商家政策版本和六条规则保持。当前进度只看tasks/todo.md顶部。

- `knowledge.json`：16个独立单元，6条受控合成政策逐字沿用、10篇仓库来源绑定的流程整理。三家同文模板只计16条，不是48份独立政策；引用时每家映射到本店原文件/hash。源码`validate`逐家验证规则一致，没有跨店借政策。
- `queries.json`：60条Codex合成问题，30语义家族×两种表述，40开发/20冻结验收，家族不跨组。48条可回答、6条需实时工具、6条知识库未提供；开发32/4/4、验收16/2/2。来源/构造者相同，验收是冻结工程验收，不称独立盲测或真实用户评测。
- `references.json`：项目行为依据、外部冻结政策目录、既有成熟系统固定源码目录，以及本次核查的官方页面；外部材料不成为本店退款资格或业务承诺。
- 必要依据是知识单元集合，允许集合间OR、集合内AND；匹配Query只输入原问，不把标签输入检索。关联`related_ids`来自全局单行金额规则，不根据问题标签生成。实时题不因找到相关文档就算问题已解决。

单元比较为BM25/dense/三路RRF/RRF后关联金额规则/GPU候选并集CE/GPU全库CE/直接全库读取。固定参数先冻结，开发集选定候选后再执行验收。源码和来源hash见`manifest.json`，计量与结果见本批报告。检索器是文件内存实验，真实PG路径单列复测，不能混报。
