## 3. 任务粒度

todo中的T编号是可追踪工作包，内部列出小步骤。执行模型每次优先完成一个小步骤，通常修改3–5个核心文件并留可运行结果。脚手架自动生成例外；若单步骤超过8个核心文件或涉及多个事务设计，先在原任务下拆分，不一次生成整个仓库。

v1.0粗估180–280小时已不覆盖新增深度。v1.1暂按额外60–100小时，即总240–380小时作工作量参考（含学习、实验和修复，不是承诺）。前2个里程碑及T35完成后按实际耗时重估；不能用模型自动生成速度替代集成/故障/评测成本。首个退款切片尽早交付。

## 4. 风险与应对

| 风险 | 处理 |
| --- | --- |
| Boot/Cloud/SCA补丁不匹配 | T00先做真实最小集成并锁版本 |
| 本地资源不足 | 按切片启动、观测profile后开，保留核心语义 |
| 需求逐渐扩大 | 只实现一个line全量、三类场景、原地址原SKU |
| 双语言协议漂移 | T02 Schema/OpenAPI fixtures，CI同步校验 |
| 并发重复补救 | commerce统一权益+目标start协议，早期故障实验 |
| Agent不比固定流程好 | 相同条件对照，允许以成本/可靠性而非准确率提升交付 |
| 模型访问/预算不足 | mock先实现，live实验真实需求单列，不伪造数据 |
| 文档很完整但无法运行 | 每个G门槛要求可演示行为及真实命令输出 |
| Harness只有名词没有独立实现 | 模块接口、H系列验收、T35–T39与R07/R13/R14逐一对应 |
| 历史回放没有覆盖新策略分支 | REPLAY_MISS显式终止，另用合成world评测，不伪造工具结果 |
