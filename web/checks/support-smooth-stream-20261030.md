# 买家客服流式与退款卡片稳定性（2026-10-30）

## 问题与证据

用户实际感受为正文整段突然出现、退款申请返回时网页抖动。此前最新70字虽有4个answer.delta，但224ms内发完，Java SSE每250ms读取事件，多个片段可能同批抵达。前端直接展示整批文字，并在answer.committed清空临时气泡、直接换完整消息；文字与退款卡片各自触发scrollTop跳底。不能仅用“接口支持流式”当体验验收。

## 实现

- 新增support-reveal.ts，只对当前页面观察到的进行中run逐帧显示真实文本，使用字素分段避免拆开emoji，首字立即呈现、积压自适应追赶，完成后最多1.2秒收尾。保持已显示前缀；校正/重试/失败/换会话立即清理旧文本；历史回复不重播；隐藏页和减少动态效果偏好直接追上。权威消息、输入版本及领域状态即时接收，不受动画延后。
- 临时段落、头像占位宽度和元数据高度与最终回复一致，最终消息出现前隐藏同run完整副本，避免同屏重复/突然全量替换。
- 退款自动prepare仍只消费已提交的正式助手消息，并等待正文显示完再发起；确认提交仍由买家点击，动画不创建授权或退款。核对期间用稳定占位，输入区为退款入口保留高度。
- 统一ResizeObserver与逐帧底部跟随；文本/字体/图片/退款卡片的布局变化共用一个跟随入口。滚轮、触摸、滚动条、键盘阅读意图取消自动跟随，保留回到最新按钮；禁用浏览器原生滚动锚定与应用滚动竞争。
- 第二轮真实采样发现额外原因：正常发送的pending/“问题已发送”顶部提示先将聊天区从93顶到158px，回复返回又清除。新增回归先红，删除重复发送提示，正常等待直接在聊天区呈现；未知写入和错误仍有原请求恢复入口。
