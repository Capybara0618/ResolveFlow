# ResolveFlow 现代商城体验打磨计划

制定日期：2026-10-30。依据：用户要求先完整规划，再依次打磨各模块，最终形成视觉统一、操作自然、体验成熟的商城项目。

本文规定目标、顺序和验收方法；**实际进度只维护在 [tasks/todo.md 顶部](../../tasks/todo.md)**。既有功能与历史通过结果保留，不将旧截图或自动化通过直接当作本计划的新验收。

## 本轮执行节奏（用户2026-10-30最新要求）

先按 M1 至 M7 顺序完成整批代码；期间做相关离线回归、类型与构建检查。各小步不启动/重启服务、不逐页进行浏览器验收，也不逐模块等待用户审查。整批代码齐备后进入 M8，集中启动一次，统一完成三角色实际操作和视觉验收。M0 样板作为设计参照，不再作为逐项开工审批门槛。用户本条要求优先于下文原先分模块实机验收的节奏。

## 1. 最终要达到的体验

用户从浏览商品到完成购买、咨询、退款，始终知道自己在哪里、正在处理什么、下一步如何操作。切换页面不丢阅读位置，输入内容不被普通刷新覆盖，异步结果不会挤动关键按钮或输入区；同一种操作在不同模块有一致表现。

视觉延续现有暖白、米色和深绿，保留已认可的字体与优质商品图。重点解决布局比例、信息主次、控件细节和操作节奏，不以添加装饰或扩大功能数量代替完成度。

目标为桌面网页：主要审查 1280×720、1440×900、1920×1080。窗口缩窄时检查不溢出、可操作；不另立移动产品计划。

## 2. 审查结论与实施原则

| 已观察到的问题 | 对应实施原则 |
| --- | --- |
| 同色但字号、按钮、边框密度与留白不一致 | 先统一基础尺度与组件，再让页面围绕各自任务布局 |
| 购物车宽表格空白大，聊天多栏挤压中心 | 先确定阅读顺序与操作位置，再决定容器与栏宽 |
| 刷新、辅助入口、主要动作视觉权重接近 | 每个当前任务区明确一个主要动作；次要入口降低权重 |
| 正文、资料栏、申请卡重复商品与诉求 | 信息指定一个主要承载区，按需查看补充资料 |
| 各页分别实现加载、保存、编辑与删除 | 共用交互约定；业务状态、请求幂等与权限仍在原组件/服务负责 |
| 多层样式覆盖累积，局部调整容易互相影响 | 每迁移一个模块，就收拢其相关旧规则；不再新增一层全站补丁 |

已有订单/商城状态保留、客服逐帧呈现、稳定滚动与新版确认框，是可复用基础，按新视觉标准检查后继续使用。

## 3. 设计与交互基准

### 3.1 视觉

- 字体：界面沿用 Resolve Sans；阅读正文可使用已认可的 Resolve Reading。表单、导航、金额与按钮使用界面字体，不将整页改成阅读字体。
- 字号初始尺度：页面标题 24–28px，分区标题 17–20px，正文/表单 14–16px，必要辅助信息 12–13px。由样板实看调整后冻结，不把所有内容统一放大。
- 空间：以 4/8px 为基础，常用分区间距 24/32/48px；正文宽度有约束，大屏不无限拉长。
- 表面：页面背景、工作表面、悬浮层三级即可；用对齐和间距组织内容，边框用于分组与输入，不给每段文字都套卡片。
- 控件：普通操作约 40px 高，主要操作可用 44px；统一内边距、禁用、悬停、聚焦和按下状态。危险动作明确表达，不靠颜色单独区分。
- 图片/图标：商品图比例与裁剪统一；商家、买家、助手身份一致；使用现有线性图标体系，删除装饰性箭头、三角与不必要标签。素材缺口先列清单，不无目的重新生图。
- 文案：短、具体、面向当前角色。保留用户完成操作需要的信息，删除重复解释、技术过程与无意义口号。交易真实属性和必要业务说明在相关操作处准确表达。

### 3.2 操作连续性

- 前进进入正确的页面起点，返回恢复此前筛选、页码、选项及阅读位置；不同历史条目分开记忆。
- 临时确认/编辑先退出当前层，再返回上一页。遮罩、关闭、Esc 与焦点恢复一致；提交中沿用当前业务限制。
- 有内容时刷新保留原内容并标明处理状态；首次慢读使用对应结构骨架。失败不能显示成空数据或成功。
- 保存/加入购物车等轻操作使用就近反馈，避免顶部横幅撑高全页；明确成功后才更新权威结果。
- 普通刷新不覆盖正在编辑的内容；版本冲突、失败或结果未知时保留原输入与合法恢复路径。
- 内容过渡约 140–180ms，按钮反馈约 120ms；只在帮助理解变化时使用。遵循减少动态效果偏好，不为动画延迟业务确认。
- 聊天输入区、主操作区保持稳定；用户向上阅读后不被强拉回底部。自动聚焦不意外移动页面。

## 4. 按模块执行的顺序

### M0：基线、设计标准与可交互样板

目的：先校准“现代、成熟、舒服”的实际效果，避免全站按错误标准铺开。

工作：
1. 固定当前缺陷清单与已有截图证据，区分代码确认、视觉判断和待实机验证。
2. 制作商城首页/商品详情/购物车/确认订单四页可交互预期稿，使用既有真实图片素材。
3. 稿件连通搜索/分类、规格切换、数量、加购、勾选、结算及返回；只在独立预览中演示，不调用交易或模型接口。
4. 同时提供空购物车、无搜索结果、加载、保存反馈和确认框的可检查状态。
5. 四页预期稿作为比例、字体、信息主次与操作节奏参照，按用户最新要求直接落实代码，整批完成后集中审查。

产物：本计划、独立可交互预期稿、设计基准、审查说明。进入 M1 的条件：样板已交付，按用户最新指示继续实施。

### M1：统一基础与导航外壳

工作：统一颜色/字体/间距/控件尺度，品牌、导航、主要/次要/危险按钮、表单、分页、提示、骨架和弹窗；清理冲突选择器与历史展示链专用覆盖。买家与工作台保持同一基础语言，允许不同密度。

主要位置：`web/src/ui/tokens.css`、`interface.css`、`display-typography.css`、`interaction-motion.css`、`ReviewDialog.vue`、`ListPagination.vue`、`App.vue`。按组件拆小步，不一次全改。

验收：品牌不随路由改变大小；按钮和表单有完整状态；弹窗不开启背景滚动、不改变背景布局；键盘焦点可见；原权限和忙碌阻止规则保持。

### M2：商城浏览与购买主链

工作：
- 首页/搜索/店铺：导航与内容对齐，主视觉不压迫商品，分类/排序类现有筛选与分页层级清楚；商家归属可识别。
- 商品：主图与购买区比例、标题/价格/规格/数量/主动作顺序；评价入口、参数和配送售后说明按阅读顺序安排，避免正文挤入购买操作区。
- 购物车：缩小无意义空白，统一商品行和金额列；多店结算规则通过分组呈现，结算动作明确；保留勾选和位置。
- 确认订单/现有付款页：地址、商品、总额和提交动作清楚；修改规格与地址有自然返回；提交中、失败、未知结果有一致反馈。

主要位置：`MarketplaceWorkspace.vue`、`ProductGallery.vue`、`ProductReviews.vue`、`CartWorkspace.vue`、`AddressPicker.vue`、`BuyerOrders.vue` 与对应 CSS。

验收路径：第2页商品→指定规格/数量→购物车→取消/重新勾选→确认订单→修改地址/返回→列表原页原位；无结果、下架、价格变化、失败保留内容分别检查。展示价格与提交金额必须来自现有权威接口。

### M3：买家订单、物流、评价与售后结果

工作：订单列表控制密度，明确商品、阶段与金额；详情按状态/商品/收货物流/操作分层；评价编辑不抢占整个页面。处理中、需补充、成功、失败与结果未知各有明确结果和下一步，退款完成页不再沿用仍在进行的进度效果。

主要位置：`BuyerOrders.vue`、`ShippingSummary.vue`、`FulfillmentPanel.vue`、`ProductReviewEditor.vue`、`CustomerWorkspace.vue`、`BuyerApplicationProgress.vue`。

验收路径：订单筛选分页→详情→物流→评价→返回；售后等待→补充/确认→退款结果→回到对应订单。已退款和未知状态不能提供重复退款入口。

### M4：登录与买家账户

工作：登录/注册/找回/安全设置统一外壳和表单反馈；个人中心突出近期订单及常用入口；资料更改和头像操作有稳定布局；地址新增/编辑/删除采用统一形式；消息列表、未读和跳转清楚且保留页码。

主要位置：`App.vue`、`EnrollmentForm.vue`、`PersonalCenter.vue`、`AccountWorkspace.vue`、`NotificationCenter.vue`。

验收路径：登录→个人中心→资料编辑/头像→保存→地址编辑/取消/保存→消息第2页→会话→返回。编辑内容保留、重复提交受控、错误就近可读；敏感账号变更按既有认证流程处理。

### M5：买家助手与调查过程

工作：让聊天成为主阅读区；会话列表能区分同商品不同咨询；商品资料和依据按需查看；减少正文、右栏、申请卡重复。输入区有明确发送状态。等待/查到物流/继续调查/可申请/失败可恢复的状态转换自然；正文与申请卡出现顺序稳定。

主要位置：`SupportWorkspace.vue`、`SupportContext.vue`、`SupportBuyerReply.vue`、`SupportRefundCard.vue`、`BuyerSources.vue`、`buyer-support.css`、`support-reveal.ts`。

验收：历史消息不重播；真实输出逐步呈现、失败立即说明；向上阅读不被抢滚动；Agent 未启动不无限等待；退款摘要金额与原因可核对。必要时修回复呈现，但不为视觉改动重写 Agent 架构。

### M6：商家工作台

按以下子模块依次实施：
1. 概览：突出可执行待办，避免相同任务统计与列表重复抢主次。
2. 交易订单：分页/筛选/详情/发货的连续性及金额层级。
3. 商品、图片与店铺资料：编辑表单、图片顺序/预览、保存反馈一致。
4. 商品评价：列表与回复聚焦当前买家，返回保留页码/输入。
5. 咨询核查：减少栏位挤压，客户身份明确，沟通为主、资料为辅。
6. 售后审批：客户诉求→事实/依据→当前建议→决定，明确金额和动作；处理中/冲突/未知结果正确处理。
7. 退款规则与已有人员/协作入口：排版、分页、阅读密度与相关弹窗统一，不扩写生效政策。

主要位置：`AdminOverview.vue`、`AdminTrades.vue`、`AdminProducts.vue`、`PresentationEditor.vue`、`MerchantReviews.vue`、`SupportWorkspace.vue`、`MerchantCaseDetail.vue`、`ReviewerWorkspace.vue`、`AdminPolicies.vue`、`AdminPeople.vue`。

验收路径：待办直达→当前记录→核查/回复/审批→结果→回列表原筛选页；买家只看到对其公开的结果，操作过程留在有权限的工作台。多条记录、长标题/长依据、有失败和无待办分别检查。

### M7：平台管理员与运行查看

工作：商家/买家管理统一列表、搜索和分页能力的呈现；创建/编辑/启停/密码相关操作采用同一表单与确认规则；Agent 运行查看保持面向管理员的状态、过程、失败与来源层次。涉及分页缺口先确认正式接口能力，再补契约和实现，不做只对已加载记录生效的伪分页。

主要位置：`PlatformWorkspace.vue`、`SupportOperations.vue`、`foundation.css` 及现有管理客户端；按实际缺口同步现有 Java 接口。

验收：各入口当前选择明确，操作后列表不重置，失败不被表示为零记录，长编号不撑破布局；不把后台技术信息带入买家界面。

### M8：全链体验验收与交付

工作：使用专用账号按真实角色完成购物、订单、评价、咨询、调查、买家确认、商家审批、退款结果；另外核对一条失败/恢复路径。沿用既有数据和样本，不清库或删除购物/退款历史。

验收：
- 正常路径走通，每一步能理解当前状态和下一动作。
- 主要内容无重叠、裁切、横溢；真实更新不推动输入区或主要操作区突然跳动。
- 搜索/页码/勾选/阅读位置/编辑内容在对应返回路径保留。
- 主次按钮、字号、数字、图标、图片与弹窗跨角色一致。
- 加载、空结果、失败、提交中、成功、冲突与未知结果均有明确表现。
- 关键键盘操作、关闭与焦点恢复可用；减少动态效果受到尊重。
- 必须通过相关自动化及类型/构建检查；实机检查视觉与手感，不能用测试数替代。

产物：按角色的验收报告、最终实机截图、已知问题与处理结论、可录制操作路线。README 图片/视频素材仅在这一步通过后更新。

## 5. 每个模块的执行流程

1. 先读该模块源码/现有测试/最近证据，列出具体问题及用户可感知的后果。
2. 按重要程度选择一组连续操作，先布局与层级，再控件细节，最后过渡与反馈。
3. 每小步通常修改3–5个核心文件，必要的状态/失败回归先红后绿；纯样式不编写复述 CSS 的测试。
4. 每个子模块完成相关离线测试和构建；真实界面、视觉、手感与业务整链留到 M8 统一验收。准确记录未运行，不以旧截图顶替。
5. 核对修改清单和证据，中文提交、正常推送并确认远端；推进下一子模块。进度写入 todo 顶部，重要共性问题更新 architecture-evolution。
6. 有新证据才重跑或扩大测试。达到明确标准后收口，避免同一处无限微调。

## 6. 范围、依赖与停止条件

- 沿用现有 Vue、Java 三服务和 Python Agent，不增加前端框架/动画库/微服务；必要后端缺口按原职责修复。
- 不引入库存、真实支付、优惠券、会员等新业务；本计划衡量现有功能完成度。
- 保留原权限、主体隔离、授权 revision、资金上限、退款一次成功、UNKNOWN 原请求恢复等约束。
- 原数据、已有用户修改和四个无关工作区文件保持；不为截图伪造生产用户、指标或交易结果。
- 收费模型验证只放在需要真实 Agent 行为的验收环节，先复用现有样本与离线检查；不购买资源或公开部署。
- 浏览器被关闭时继续可独立完成的设计、实现和自动化；最终实机项明确待验，不绕过访问设置或宣称完成。
- 模块存在布局重叠、无响应/无限等待、输入丢失、无法恢复的失败或错误交易动作，不能标完成。次要审美意见集中一轮处理，不无限扩展。

## 7. 立即执行的第一步

先交付 M0 四页可交互预期稿，并说明与当前界面的具体差异。样板应能直接体验“浏览→选择→加购→结算→返回”，展示正常和失败/空态的设计。现按用户最新要求执行 M1 至 M7 代码与离线检查，最后 M8 集中实机验收。
