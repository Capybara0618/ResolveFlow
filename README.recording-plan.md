# README 录制分镜

用一笔耳机订单，讲清楚从购买到售后的完整体验。镜头跟着用户操作走，字幕简单直接，让人看完知道这个项目能做什么、用起来怎么样。

## 1. 想让访客记住什么

从浏览商品、询问订单，到商家处理售后，把整个过程做成可以亲手操作的产品。先让访客看到怎么用，再通过源码、设计和实测了解怎么实现。

首屏文案建议：**从选购商品到售后退款，一站走完。**

## 2. 交付素材

| 素材 | 内容 | 位置与用途 |
| --- | --- | --- |

| B | 3–5 分钟完整视频及一张封面 | 从 README 封面链接进入，包含购前、角色切换与后台准备说明 |
| C | 买家聊天与待确认退款卡 | 证明自然表达、金额/原因核对、用户明确确认 |

预定正式文件名为 `docs/assets/readme/experience.gif`、`demo-cover.png`、`buyer-confirm.png`、`merchant-review.png`、`operations.png`。素材按这些名称导出。完整 MP4 优先放独立发布附件，仓库保留轻量图与字幕/说明；录制完成后确定视频地址。

静态图直接在 README 显示，完整视频使用封面链接；动图预计宽约1000–1200px、8–12fps，以正文可读和可加载为准，目标约8MB以内；若实测过大，缩短动图，完整细节放视频，原始录屏单独保存。

## 3. 场景与准备

固定商品建议：松间数码无线降噪耳机，黑色、1件。录制时以页面实际金额为准。

使用新演示订单和属于本次演示的会话。买家与商家分开标签登录，平台另用标签；保持同一店铺、商品规格、订单行与申请。选取属于这笔订单的会话作为录制画面。

先确认三 Java、Agent、消息系统、政策索引及前端健康，确认没有意外待运行任务。录制浏览器约1280×720或1440×900，保留100%缩放；选择一个尺寸贯穿。预查该尺寸下买家确认按钮、商家操作与结果均可见。

正式录制前完成一次独立准备/彩排。彩排与正式录制分别保存订单记录。导出前检查画面中的账号信息、密码和配置密钥。

## 6. 参考输入与成功判断

参考输入如下，录制时按助手实际回复继续操作：

- 查物流：“耳机还没收到，帮我看看物流到哪里了？”
- 准备申请：“我没有收到耳机，请帮我准备退款申请，金额和原因我核对后再确认。”
- 编辑原因示例：“这件耳机一直没有收到，申请退还本件商品实付款。”
- 完成追问：“现在这笔退款办好了吗？退了多少钱，还需要我做什么？”

助手根据订单事实回答，缺少资料时继续查询或交给商家核实。结果画面以实际退款记录为准。

商家核对材料与订单事实，例如“模拟承运记录LOST且无有效签收，与本件商品及客户未收货材料一致”。商家审批仍使用当前有效建议/授权与页面操作。

## 7. 物流场景的可复现准备

新订单先通过商家正式页面模拟发货；再用已有工具读取本次订单当前版本，只推进该订单的物流。

仓库根目录的 PowerShell 模板如下。订单id来自新订单，版本来自inspect结果；请求key在第一次提交前生成并记录，重试时沿用同一key和payload：

```powershell
$demoOrderId = '<本次新订单id>'
$demoMerchantId = 'M-1001'
.\agent\.venv\Scripts\python.exe scripts/logistics_simulator.py inspect `
  --order-id $demoOrderId --merchant-id $demoMerchantId

# 填入inspect输出中的物流版本。
$demoExpectedVersion = '<当前物流版本>'
$demoRequestKey = [guid]::NewGuid().ToString()
.\agent\.venv\Scripts\python.exe scripts/logistics_simulator.py advance `
  --order-id $demoOrderId --merchant-id $demoMerchantId `
  --expected-version $demoExpectedVersion --scenario LOST --request-key $demoRequestKey
```

商家发货后，用项目提供的工具设置LOST，主视频用一句字幕交代，命令步骤放进运行说明。

截图三角色统一字号/缩放和窗口比例；金额、商品、店铺一致，字幕跟随实际状态。视频先交作者查看，确认后安排发布。
