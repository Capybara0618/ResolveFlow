## 内容复核与根因

1. **物流答复可用，但措辞还可打磨。** 正确读出IN_TRANSIT与运输延迟事件，没有说已丢失、已退款；明确当前只核查。直接展示IN_TRANSIT、反复“核验”等词，仍偏系统语言。
2. **政策答复来源真实、覆盖不够贴题。** 实际query是“未收到货 售后政策 需要提供的材料”，top3为未发货、签收争议、损坏，未包含丢失条款。回答照来源展开三个分支，未把“已经发货、当前延迟”的上下文作为主线，材料部分是一般建议而非政策明确清单。不能据本轮宣称RAG准确率达标。待处理的是query/已知事实衔接、候选覆盖与答复聚焦，不应先换框架或盲加重排。
3. **人工指引存在状态与页面不匹配、重复。** 模型只查了指南，未继续追旧物流任务，尊重不退款；但它指导点击“请商家核查”。该按钮在新核查单场景存在，**当前已有核查单时隐藏**，应指向“补充给商家”。实际Python context没有ticket状态字段，静态指南/next_steps也无已有单分支；不是单纯换个按钮名。模型正文已讲步骤，`navigation.py`又固定追加同义段落，形成重复。后续应传受控核查状态并让办理步骤只渲染一次，用已保存响应离线验收。
4. **刷新需重新登录。** `web/src/App.vue`账户只在内存，整页刷新回登录；重新登录后消息完整恢复。SSE网络续接已独立通过，不能据此声称整页会话无缝恢复。会话保持属于页面体验项，需单独小步处理。

因此S3的传输与发布机制可以收口，**完整客服体验还不能冻结**。下一步先处理已有核查单指引/重复文本和刷新体验，并用有限已存样本确认政策回答聚焦；之后接R1–R3聊天退款摘要/编辑确认/原申请进度，不扩大为新Agent框架或整套付费评测。
