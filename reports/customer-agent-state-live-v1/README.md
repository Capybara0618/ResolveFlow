## 用户实际会看到什么

两阶段U05的四轮均直接完成，无纠错反馈：

1. **显示签收但没找到、可能家人代收**：读取当前物流，区分DELIVERED与实际收件人未知，不把猜测当事实。
2. **先暂停，插问申请入口**：原t1真正PAUSED，新t2负责入口；实际读指南，回答「我的售后」。
3. **继续原调查，已问家人和代收点**：原t1恢复OPEN，程序生成陈述id并按原句offset15保存CHECKS；没有凭空supersedes或记忆警告。实际读取物流和指南，正确给出「售后咨询→请商家核查→预览编辑→确认」，不重复要求已完成的排查。
4. **找到了、不核查也不退款**：直接RESOLVE原t1，停止推进，不重新读取无必要的物流，不虚构已退款或已转交。旧入口t2保留但不重复回答。

U06金额专问，两组都实际读取ORDER，正确回答实付129.00CNY、付款状态PAID。两阶段使用PAID_AMOUNT/ORDER_STATUS占位符，由程序填入；没有从商品展示或物流LOST推付款状态。两阶段另有四轮使用运输字段占位符，总计5个实际回答、10个字段，原模型决定与最终渲染均保存。

U03独立人工咨询两组均正确说明无需退款金额/无需先申请退款，给出预览编辑确认和共享选择，没有声称已提交。两阶段主intent为LOGISTICS、U06也分类LOGISTICS，但needs分别选择SHIPMENT+GUIDE和ORDER，业务来源仍正确；不能据这批宣称意图分类全面准确。
