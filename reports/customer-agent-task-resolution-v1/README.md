# 客服Agent任务推进与完成依据：离线实施结果

2026-10-22，用户要求先修三类实际问题，再做简历指标。依据[真实失败记录](../customer-agent-experience-v1/conversations.md)，按[开发方案](../../docs/customer-agent-task-resolution-v1.md)实施。**执行与完成检查已接入，真实模型行为改善尚未验证。** 本轮不启动业务队列、不收费刷分。

## 三类问题的改动

| 问题 | 实施 | 实际验证 |
| --- | --- | --- |
| 相同物流反复读取 | 最近3组实际工具名、参数、来源、错误与次数；重复合并，旧组计遗漏，完整调用账保留 | 下一次实际模型包含执行顺序/重复次数，故障→恢复分开，格式纠错不当业务行动；持久恢复输入相同，0新调用 |
| 混合诉求未查完便结束 | 已声明任务显示未解决事项和完成条件；live回答根据已接受任务检查来源、客户提问、真实失败 | 原U02不能以NEEDS_CUSTOMER掩盖未查入口；读指南后可发布；旧ANSWER省略tasks也不能绕过 |
| 独立核查与退款混淆 | 明确HANDOFF为独立核查、APPLICATION为正式退款操作，前者不要求先退款；两类操作回答绑定当前指南 | 原U03无工具直接给操作结论被拒，脚本改用独立核查意图、读取指南、给预览确认步骤后可发布 |

AgentScope仍驱动唯一循环；模型决定意图/任务与下一工具。没有关键词路由、多Agent审核或额外LLM分类。取消/暂停无需重新读指南；普通物流问询不强制查政策/指南。资格的ANSWERED须有任务关联的政策引用；入口/操作须任务关联指南，其他任务引用不能冒充该任务依据。NEEDS_CUSTOMER须blocker记录缺口及该任务答复原句中的明确提问；UNAVAILABLE须实际、相关且尚未恢复的来源失败，未读取/空检索/无关故障不能替代。

TaskBlocker是模型说明，不升级为客户事实。持久化后仅作为previous_blocker历史提示带入下一轮；四轮脚本暂停时不再携带当前阻塞，不继承旧run引用，不拿旧故障当新run失败。模型结果/工具读取仍受原fence、预算、deadline、一次纠错和防循环约束；新增模块加入运行manifest。后续新冻结包含新模块，旧清单与原始报告不改。
