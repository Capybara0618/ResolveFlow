### 唯一未通过：目标类别选错，正确答复被错误目标约束

M02/2客户说“能帮我整理一段给商家的摘要吗，先不要发出去”。理解request本身写明给商家、operation_request也是本轮原句，但intent=APPLICATION/goal=PREPARE_REFUND。出处核验通过并不能证明操作类别正确。

调查后首个RESPOND实际输出handoff_reason，内容明确“不涉及退款申请”。程序却因先接受的错误目标要求refund_reason，反馈没有回到用户目的，模型一次修正后改成退款原因，最终附退款步骤且没有独立人工摘要。原三项业务判据均未完整满足，记FAIL；没有实际Case/人工单/退款或授权写入，用户确认及资金边界仍保持。

这证明两个边界：理解原话和枚举目标可能不一致；已接受目标被当作不可纠正事实，会让答复阶段正确的语义也被压回错误方向。下一步宜核对目标与所请求产物的一致性，并在产物冲突时允许受控返回理解，不能仅要求模型把字段改成旧目标。该后续修复本批尚未实施或验证，不在失败后换题再收费。
