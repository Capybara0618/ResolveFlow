## 1. 审查对象与计分方法

- 4份官方HTML快照，3个外部主体，242个非空原文块、66个检索子块；不是当前商家生产政策库。来源为[京东总则](https://help.jd.com/user/issue/126-406.html)、[京东自营数码细则](https://help.jd.com/user/issue/325-915.html)、[小米有品自营说明](https://home.mi.com/app/shop/content?id=rb2051039f9de31b4)、[宜家官网条款](https://www.ikea.cn/cn/zh/customer-service/terms-conditions/)。判断仅针对冻结版本，不宣称这些页面今天仍为该版本。
- 29题：18道先前编写的合成政策题、11道复用官方FAQ原问法。FAQ问题来源真实，但不包含真实客户订单或FAQ答案正文。
- 复用[原始排名](../policy-document-ingestion/query-baseline.json)，核验4份原HTML的SHA、27项冻结输入、66子块的实际原文跨度，以及116份既有父章节包。完整来源/hash/定位及结果见[audit-v1.json](audit-v1.json)，输入绑定见[manifest](../../evals/rag-codex-review-v1/manifest.json)。
- **直接覆盖**：前k子块的实际字符跨度足以包含一组完整充分依据。表格按带表头的具体行核对，别的行不算命中。
- **展开覆盖**：沿原策略展开完整父章节并受原8000字符限制后，包含充分依据。缓存全文/来源与重新构造的包逐一相同才能计分。
- 一组充分依据内部是“且”，多个等价集合是“或”。重复的激活/食品例外不强制同时找齐；省略限制条件、上级否定标题或冲突条款不能算充分。
- 引用粒度是完整块/完整表格行，因此直接覆盖是保守的证据完整性检查，不是最短语义片段标注，也不是每条结果的相关性精度、NDCG或完整答案准确率。

## 5. 建议的下一批（本次未实施）

1. **先改善文档层次与检索结果组织**：将上级适用范围、否定/例外标题、来源/版本与局部条款正确关联；返回有用的同规则邻近条件，同时控制整页兜底和相同父正文占排名。保留原文及冲突，不能为省token截掉例外。这能同时处理定作、赠品、销售主体等多类问题。
2. **固定新标签比较通用检索候选**：正文dense作为原基线，比较结构路径+正文，以及dense/BM25融合后去重；是否增加重排由实际收益决定。不要直接换BM25、加多个模型或针对29题固定query。沿用同语料、同query、同k和上下文约束，分别报告直接覆盖、展开覆盖、排名和长度，不能只优化展开满分。
3. **缺语料与缺事实另处理**：订单进度/支付/库存归业务工具或操作知识，不把它们编进退款政策；需要澄清的问法不硬给答案。以多样改写/反例补充后续验证，标明合成来源，不覆盖本批标签来刷分。
4. **RAG候选稳定后再看Agent**：还需核查保存的32例实际Agent所生成的query、得到的商家政策和最终建议是否衔接。当前29题是外部政策诊断，不等于已评估32例真实循环中的每次RAG调用。本次没有重审32建议、优化Harness或重跑付费整体对照。
