## 已确认的根因

1. **已答FAQ可省略的规则，也允许未结束调查事项消失。** 程序确实保存了ANSWERED/OPEN，但required携带检查仍按status==ANSWERED豁免；更新生命周期时又只保留本轮tasks中的键。缺少持续调查事项与单轮FAQ的区别，也缺少独立于当前回答任务的事项保留。离线按保存的第二轮原始决定执行DialogueState.apply，可复现t1从OPEN直接消失；没有改动模型原决定。
2. **结束事件与答复状态仍要求模型同步两个枚举。** 找到包裹后模型两次选择RESOLVE+CANCELLED，停止意图清楚，却不符合程序要求的RESOLVE+ANSWERED或CANCEL+CANCELLED。当前反馈只说lifecycle不一致，没指出具体冲突。离线对副本仅改事件为CANCEL、或仅改结果为ANSWERED，两种都能通过状态转换。这仅用于定位校验耦合，不算真实成功，也没有修改原始轨迹或业务数据。
3. **模型可见工具说明与动作协议存在字段混淆。** capabilities展示purpose说明，但READ_TOOL不允许输出purpose；本轮3个Schema错误全部来自该字段。U05第二轮格式反馈后改正，U02却重复同样字段而停止。当前工具接口太容易因非执行参数的说明文字而中断。
4. **来源检查依赖主intent，不能覆盖答复中的附带操作指引。** U05第三轮标为LOGISTICS，既没有读取当前物流，也没读取核查流程指南；它用历史助手内容和错误页面路径组织答复，仍能发布。引用及主要意图检查不能替代完整内容核验。

后续修正重点应是：保留持续事项并明确一次性问题的结束方式；减少事件与答复状态的重复控制、给出具体冲突反馈；统一工具描述和动作Schema；将平台操作指引作为有指南依据的答复部分。先用本批失败响应做离线回归，再用新版本有限确认。不是更换Agent框架或增加RAG召回算法；本批没有调整生产源码，也没有收费重跑。
